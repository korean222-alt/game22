## 0. 30초 요약

카이로소프트 **소셜게임 스토리**를 의존성 없는 WebGL2 3D로 옮긴 리메이크.
**모바일 가로 모드 전용**, Vercel 정적 배포, PWA.

```bash
python3 -m http.server 8123     # 빌드 스텝 없음. ES 모듈이라 정적 서버만 필요
node tools/balance.mjs 12345 10 # 밸런스 시뮬레이션 (브라우저 불필요)
node tools/monster.mjs          # 보스 몬스터 에셋 검증 (브라우저 불필요)
node tools/flow.mjs             # 전체 플로우 브라우저 테스트 (42개 검사)
node tools/battle.mjs           # 상점·장비·체력·도감·1인칭 (20개 검사)
node tools/raid.mjs             # 보스 아레나 3연전·자동 전투·판매 패널 (9개 검사)
```

한 바퀴가 전부 돈다: **창업(회사명 + 지원금) → 가구 구입 → 배치 →
채용 → 기획서 → 회의 → 보스 아레나 3연전 → 아이디어 카드 →
완성 → 디버그 → 홍보 → 출시 → 운영(판매 현황) → 팬 → 랭크 → 층 구매 → 다시.**
저장/불러오기, 직원 육성·전직·환생·특성, 연구·계약·유행,
**직원 체력 · 상점과 가방 · 장비 · 도감 · 1인칭 걷기**까지 들어가 있다.

여기에 더해 **재촉과 콤보**(자동 전투에 손이 끼어드는 자리), **경쟁사와 주간
판매 차트**, **도우미 뽑기**, **절차적 효과음**, **창밖의 도시**가 붙어 있다.

**사무실은 비어 있는 상태로 시작한다.** 창업 멤버도, 책상도 없다.
책상은 사서 놓는 것이고, 앉을 자리가 있어야 사람을 뽑을 수 있다.

## 2. 반드시 알아야 할 규약

### 2.1 좌표와 방향 — 여기서 버그가 네 번 났다

- **−Z 가 북쪽.** rig 가 yaw `y` 면 바라보는 방향은 `(sin y, cos y)`.
- **의자 회전은 `yaw − PI/2`.** 좌석은 `yaw` 하나만 들고 다니고 가구
  회전은 거기서 유도한다. 두 숫자를 따로 두면 사람이 뒤돌아 앉는다.
- **`props.js` 에서 무언가를 "옆으로" 밀 때는 `(sin ry, cos ry)` 를 쓴다.**
  `(cos, sin)` 을 쓰면 90° 틀어진다. 실제로 이 실수로:
  - 책상 가림판이 앞이 아니라 **옆면**에 서서 5유닛 벽이 됐고,
  - 문틀 기둥이 벽과 나란하지 않고 **자기 문을 가로막았고**,
  - 계단이 엘리베이터 코어에서 **옆으로 13유닛 뻗어나갔다**.

  새 프롭을 추가하면 `tools/flow.mjs` 가 아니라 **경로 탐색 테스트**
  (`tools/meeting.mjs` 의 첫 검사)로 확인할 것. 벽이 생기면 즉시 잡힌다.

### 2.2 NavGrid 는 area 를 반드시 받는다

`core/bake.js` 의 `new NavGrid(mesh, y0, y1, cell, dilate, area)` —
**`area` 를 생략하면 안 된다.** 메시에는 광장과 스카이라인까지 들어 있어서,
격자가 거기에 맞춰 자기 크기를 잡고 셀 예산(900×900)에 맞추려고 조용히
해상도를 낮춘다. 그러면 `path()` 가 `no route` 를 뱉는다.
지금은 예산 초과 시 **throw** 하도록 해놨으니 조용히 망가지지는 않는다.

층마다 격자가 따로다. 하나로 합치면 모든 층의 가구가 한 장으로 융합돼
전부 막힌다 (`main.js` `build()` 참조).

### 2.3 돌하우스 컷

두 종류가 동시에 돈다.

1. **벽 디더 컷** — 카메라와 시점 사이의 벽이 4×4 오더드 디더로 녹는다.
2. **층 컷** — 보고 있는 층 위쪽이 통째로 잘린다.
   `floorY = view.floor * STOREY + BUILDING.wallH + 0.1`, 램프 0.7.

플래그는 `world/office.js` 의 `buildSite()` 안에 세 종류가 있다.

| 플래그 | 뜻 | 쓰는 곳 |
|---|---|---|
| `0` | 두 컷 모두 적용 | 실내 벽·가구 |
| `3` | 벽 컷만 면제 | 문틀·유리 프레임 등 얇은 실내 부재 |
| `SITE = 4` | **두 컷 모두 면제** | 지면·도로·주변 빌딩 |
| `CEIL_FLAG = 5` | 벽 컷 면제 + 층 컷은 **디더 없이 통째로** | 천장 슬래브, 조명, 외부 기둥, 파라펫 |

**지붕을 SITE 로 하면 안 된다.** 아래층을 볼 때 같이 사라져야 한다.

**천장은 반드시 `CEIL_FLAG` 다.** 층 컷의 페이드 구간은 `11.9 ~ 12.6` 인데
천장 슬래브(`12.45~12.95`)와 조명(`12.35~12.73`)이 정확히 그 안에 놓인다.
`3` 을 쓰면 픽셀의 몇 %만 살아남아 **바닥 전체에 흰 점이 뿌려진다** — "그래픽이
깨진다" 는 제보의 정체가 이것이었고, 조명은 격자 간격 그대로 얼룩덜룩한
직사각형으로 보였다. 외부 기둥(0~13)도 위쪽 0.7 유닛이 같은 구간에 걸려
외벽마다 얼룩이 졌다. 천장·지붕은 실루엣을 부드럽게 할 이유가 없으므로
깔끔하게 자른다. 새 야외/천장 프롭을 추가하면 이 표를 보고 플래그를 고를 것.

### 2.3.1 배치 구역은 곧 빈 바닥이어야 한다

`PLACE_ZONES` 안에 건물 설비가 서 있으면, 파란 구역인데 유령이 빨갛게
변하고(설비의 solid 가 `clearOfWalls` 에 걸린다) 놓인 가구와 설비가 눈으로
겹쳐 보인다. 사물함·폰 부스·서류함·창가 스툴이 그렇게 서 있었다.
설비를 옮기거나 구역을 줄여서 해결했고, **다시 확인하는 법**은 다음과 같다:
`buildOffice()` 의 solids 를 층별 Y 창(`f*STOREY+1.0 ~ +5.5`)으로 거른 뒤
`placeZones(f)` 의 사각형과 교차시켜 0 이 나와야 한다.

### 2.4 회의 연출의 프레임 독립성

`main.js` 의 프레임 루프는 `dt` 를 **0.1초로 클램프**한다. 저사양 기기에서
2fps 가 나오면 걷기가 1/20 속도가 되고 회의가 영원히 안 끝난다.
그래서 `playMeeting()` 은 **4.5초 데드라인**을 두고 `crew.forceSeat()` 으로
남은 사람을 자리에 순간이동시킨다. 회의 로직을 손대더라도 이 안전장치는
남겨둘 것 — 없으면 느린 폰에서 게임이 멈춘 것처럼 보인다.

### 2.5 층을 사면 월드를 다시 짓는다

`View.setFloorCount(n)` → `build()` 전체 재실행 (AO 굽기 + 층별 NavGrid).
폰에서 몇 초 걸리므로 `body.busy` + `#busy` 배너가 뜬다.
**`bootStep()` 은 null-safe 여야 한다** — 부트 오버레이는 이미 제거된 뒤다.
(이걸 놓쳐서 "층을 사면 돈만 나가고 아무 일도 안 일어나는" 버그가 있었다.)

## 3. 밸런스 — 지금 숫자와 그 이유

### 3.1 도달 곡선 (10년 × 3시드, `tools/balance.mjs`)

| | 랭크 | 출시작(누적) | 평론가 | 명예의 전당 |
|---|:-:|:-:|:-:|:-:|
| 1년차 | 4~6 | 12~16 | 23~28 | 0 |
| 2년차 | 11~12 | 25~36 | 31~34 | **첫 등재 (5~7)** |
| 3년차 | 13 | 38~52 | 33 | 17~20 |
| 5년차 | 14~15 | 65~83 | 33 | 43~47 |
| 7년차 | 15~16 | 94~117 | 33~35 | 72 |
| 10년차 | 16~17 | 141~167 | 35~36 | 111~116 |

이건 **완벽하게 플레이하는 AI** 의 곡선이다. 사람은 이만큼 못 돌린다.
사람 손의 데뷔작은 12시드 평균 **평론 12/40 · 61초 · 주 넘김 1.4회** 다
(레벨 1 세 명, 밥 없이).

자동 전투로 바뀌면서 1~2년차가 크게 앞당겨졌다. 예전에는 데뷔작 하나에
296턴 · 33주가 들어서 1년차 출시작이 **한 편**이었고 평론이 8/40 이었다 —
점수판이 아무것도 말해주지 않는 구간이 2년이나 됐다.

첫 명예의 전당(32점)은 **핵심 6명이 두 번째 전직을 마치는 시점**에 온다.
우연이 아니라 구조이므로, 전직 조건이나 `maxLevel = 30 + tier*30` 을
건드리면 이 시점이 통째로 움직인다.

### 3.2 품질과 평론의 곡선 (`game/project.js` 상단)

```js
const QCAP = 999, QSCALE = 560;   // 품질 = 999(1 - e^(-x/560))
// 평론가 1인 = 2.6 + 2.4(1 - e^(-v/45)) + 5.0(1 - e^(-v/430))
//   두 겹인 이유는 3.10 참고: 한 겹으로는 데뷔작과 10년차를 동시에 못 맞춘다
const CBASE = 2.6, CFAST = 2.4, CFAST_S = 45, CSLOW = 5.0, CSLOW_S = 430;
```

`x` = **1인·1타당 기여** (예전에는 1턴당이었다 — 자동 전투에서는 빠른 사람이
더 자주 치므로 분모가 `project.strikes` 다). 창업 ~10 에서 성숙기 ~450 까지 간다.
`project.rawPerSlot` 에 그대로 담아두므로 시뮬레이션에서 바로 볼 수 있다.

곡선이 반드시 포화형이어야 하는 이유: 능력치가 레벨×전직×의욕×궁합×
개발방식으로 **곱해지며** 네 자릿수를 넘어간다. 선형으로 두면 2년차에
차트를 벗어난다.

### 3.3 처리량(연간 출시작)을 결정하는 것

전투가 스태미나를 먹지 않게 되면서 이 식이 통째로 바뀌었다. 이제 한 게임에
드는 것은 **착수 스태미나 한 번**과 **팀의 체력**이다.

```
연간 출시작 ≈ 48주 ÷ (게임 하나가 먹는 주 수)
게임 하나가 먹는 주 수 = max(
    착수 스태미나 ÷ 주간 스태미나,          # 보통 1주 미만
    라운드 수 × 0.040 ÷ 주간 체력 회복(78%)  # 실질 병목
)
```

- **주간 스태미나**: `data.js` `rankInfo().staminaMax = min(38, 8 + rank)`
- **착수 스태미나**: `data.js` `devStamina(platform, grade, seriesN)` → 2~9
- **라운드 수**: `project.js` `raidRounds()` → 22~62 (플랫폼·장르·등급·시리즈)

**라운드 수의 상한(62)이 핵심이다.** 보스 HP 가 팀의 세기를 따라가므로,
상한이 없으면 성숙한 스튜디오도 데뷔작과 같은 시간에 대작을 찍어낸다. 반대로
상한이 너무 낮으면 대작이 소품과 구별되지 않는다. 처리량이 이상해지면
**`RAID.rounds` / `RAID.maxRounds` / `HP.turnCost` 세 개부터** 볼 것.

`project.scale`(옛 HP 식)은 전투에서 빠졌지만 시장 규모·경험치·버그 수가
여전히 읽는다. 야심의 절대 크기는 팀과 무관해야 하기 때문이다.

### 3.4 팬 → 랭크

```js
RANK_UP_FANS = 900 × 2.2^(rank-1)     // data.js
fansGained  = users × 0.11 × (명예의전당 1.5) × 홍보 × 스타개발자   // economy.js
users       = pull × 26 × 플랫폼 × 수익모델 × ... × fanBoost(상한 9)
```

`fanBoost` 상한이 없으면 유저→팬→유저로 자기를 먹여 2년차에 폭주한다.

### 3.5 성장의 느린 길 (절대 막히면 안 되는 것)

- 아이템 = 빠른 길. 돈 + 스태미나(`trainStamina = 1 + level/22`)를 쓴다.
- **출시 = 느린 길.** `state._completeProject()` 에서 팀원이
  `xp = 20 + hpMax/300 + 평론×2` 를 받는다. `expToNext = 18 × level^1.15`.

이게 없으면 돈을 안 쓰는 플레이어가 **레벨 3에 영구히 묶인다**.
`tools/sloppy.mjs` 가 정확히 그 상태를 검사한다.

### 3.6 창업 지원금과 긴급 지원금

**창업 지원금 `STARTUP_GRANT = 100,000`** 과 **창업 축하 편지의
`WELCOME_GRANT = 50,000`** 이 시작 자본의 전부다. 별도의 시작 잔고는 없다.

예전에는 지원금 하나로 180,000 이었다. 총액을 크게 줄이지 않으면서 **절반을
편지함 안으로** 옮긴 이유는 둘이다: 첫 화면에서 당장 쓸 수 있는 돈이 줄어
"책상 한 개를 어디에 놓을까" 가 진짜 선택이 되고, 편지함이 게임 첫 분에
한 번은 반드시 열리는 곳이 된다.

기본 책상 3개(27,000) + 신입 3명(약 20,000) + 피처폰 프로젝트 한 편(25,000)
까지는 지원금만으로 되고, 사무실을 사람 사는 곳으로 만드는 값은 편지에서
나온다.

**긴급 지원금**은 예전의 "조용히 40,000 채워주기"를 대체한다.

```js
amount = max(30,000, 120,000 × 0.72^n, need)      // data.js rescueAmount
need   = 가장 싼 플랫폼 개발비 × 1.8 + 주간비용 × 4   // state._rescue
morale = −(1 + min(3, n))
```

`need` 항이 핵심이다. 이게 없으면 지원금이 게임 한 편 값 아래로
내려가고, 회사는 **살아는 있는데 아무것도 못 하는** 상태가 된다.
파산과 똑같은 막다른 길에 절차만 하나 더 붙은 셈이다.
`tools/sloppy.mjs` 가 실제로 8년차에 거기 갇혀서 이 항이 생겼다.

정상적인 탈출구는 여전히 **계약 일감**(랭크 1에 14,000~42,000):
스태미나만 쓰고 의욕은 깎이지 않으니 언제나 지원금보다 싸다.

`tools/sloppy.mjs` 로 8년 돌리면 파산하지 않고 38편을 내놓지만
유저가 바닥(400명)에 붙어 랭크 3에 머문다.
**"죽지는 않되 아무것도 나아지지 않는" 상태가 설계된 하한선이다.**

### 3.7 버그 개수와 디버그

```js
scale = 8 + 12 × log2(1 + hpMax/4500);   bugs = scale × (1.5 − min(1.2, 조작성/70))
fixed = max(팀 기여도, 남은 버그 × 0.3) × (0.7~1.3)          // project.debug
```

HP 에 **선형이면 안 된다.** 예전에 중반 프로젝트에 163개가 붙었고,
디버그 스무 번은 선택이 아니라 노가다였다.

`debug()` 가 **남은 개수의 비율**을 잡는 것도 같은 이유다. 창업 멤버가
사라지면서 첫 게임은 레벨 1 신입들이 만들게 됐고, 조작성이 바닥이라
버그가 50개씩 나온다. 그 자체는 옳다 — 조작성이 스탯인 이유가 그거다.
하지만 한 번에 6개씩 지우면 여덟 번을 눌러야 한다. 비율 항이 붙으면
개수와 상관없이 대여섯 번 안에 끝난다. `tools/flow.mjs` 가 개수가 아니라
**누른 횟수**를 검사하는 것이 이 규칙의 표현이다.

### 3.8 책상이 곧 정원

랭크는 `staffCap` 을 올리지만, 실제 채용 한도는 **빈 책상 수**다
(`state.freeDesks()`). 사무실과 인사를 잇는 유일한 규칙이고,
게임이 채용 화면이 아니라 가구점에서 시작하는 이유다.

배치 구역에 들어가는 기본 책상 수: 1층 10개, 2~5층 18~20개.
랭크 상한(24명)보다 넉넉하다 — 이 수치는
`world/office.js` 의 `PLACE_ZONES` 를 건드릴 때마다 다시 재볼 것.

### 3.9 쾌적도

```js
per = Σ가구 comfort / 직원 수;   t = 1 − exp(−per/7)
moodGain  = t × 0.55      // 주간, 유휴 직원 의욕이 오를 확률
planBonus = 1 + t × 0.18  // 기획력 배율
```

**1인당**으로 재는 게 요점이다. 두 명 사무실에 소파 열 개는 좋은
사무실이 아니라 창고다. 포화 곡선이 없으면 가장 싼 전략은 모든 층을
₩2,500 화분으로 도배하는 것이 된다.

### 3.10 체력 경제 — 이제 **전투의 유일한 자원**이다

```js
HP = { turnCost: 0.040, weekly: 0.78, tired: 0.40, minMult: 0.50,
       attackEvery: 4, bugCap: 8 }        // data.js
hpMax = 56 + level*3.2 + talent*26 + 환생*12
```

스태미나와 체력을 갈랐다. **스태미나는 게임을 만드는 데** (기획서 · 개발 착수 ·
디버그 · 교육 · 계약), **체력은 보스를 잡는 데** 쓴다. 배틀 턴은 이제 스태미나를
한 점도 먹지 않는다.

`turnCost` 는 0.030 → 0.040 이고, 주간 회복은 0.70 → 0.78 이다. 자동 전투에서는
"턴" 이 아니라 **개인의 한 방**마다 빠지므로 한 풀로 25타가 나온다. 실측(12시드
평균, 밥 없이): 데뷔작 26라운드 = 주 넘김 1.4회, 후반 62라운드 = 2.8회.
그 리듬이 상점을 선택지로 만든다 — 컵라면 하나가 주 넘김 하나를 없앤다.

**보스의 반격 수치도 같이 내렸다** (`BOSS_MOVES`, 약 -35%). 예전 값은 "버튼을
눌러야 턴이 도는" 전투를 전제로 잡혀 있었는데, 자동 전투에서는 보스가 자기
게이지로 훨씬 자주 친다. 그대로 두니 데뷔작 한 판에 팀이 두세 번 쓰러졌다.
`minMult` 가 0 이 아닌 이유는 설계 원칙 그대로다 — **굶은 팀은 느려질 뿐
멈추면 안 된다.** 체력이 낮으면 공격 주기도 최대 1.9배까지 느려진다
(`project.js` `strikePeriod`).

`power()` 안에 `staminaMult(s)` 가 들어 있으므로 체력은 데미지와 품질에
**동시에** 걸린다. 이걸 바꾸면 3.1 의 도달 곡선이 통째로 움직인다.
바꿨으면 반드시 `balance.mjs` 를 3개 시드로 다시 돌릴 것.

**보스의 반격이 남기는 버그는 `bugCap`(8) 에서 멈춘다.** 상한이 없으면
긴 프로젝트일수록 버그가 선형으로 쌓여 디버그가 노가다가 된다 — 3.7 이
경고하는 바로 그 실패 모드다. 기본 곡선도 체력 도입에 맞춰
`8 + 12·log2` → `7 + 10·log2` 로 내렸다 (중앙값 21~24개, 디버그 1~2회).

### 3.11 상점과 장비

장비는 `staff.js` 의 `gearAbility()`(능력치)와 `gearAxis()`(품질 축) 둘로
들어간다. **품질 축 쪽이 핵심이다** — 사운드 담당의 피아노가 완성작의
화제성·임팩트를 실제로 올리기 때문에 "누구에게 무엇을 사줄까"가 선택이 된다.
새 장비를 추가할 때는 `axis` 합이 0.2 를 넘지 않게 할 것: 한 사람이 3칸을
같은 축으로 채우면 그것만으로 품질이 배가 된다.

### 3.11.5 스태미나의 시계와 다음 주의 값

두 가지가 같이 바뀌었고, 하나만 떼어 놓으면 게임이 막힌다.

```js
STAMINA_REGEN = 180        // 초/1점 — state.js. 벽시계로 잰다
staminaMax    = min(46, 10 + rank*1.05)     // data.js. 랭크 1 에 11
WEEK_COIN = 1, FREE_WEEK_SKIPS = 1, MAX_WEEK_COIN = 3   // state.js
```

**스태미나는 이제 실제 시간으로 찬다.** 3분에 한 점이고, 게임을 꺼 둔 사이에도
차므로 계산은 `Date.now()` 로 한다 (`state.tickClock`). 순수 시뮬레이션 안에서
벽시계를 보는 유일한 자리이고, `tools/balance.mjs` 는 이 함수를 부르지 않으므로
밸런스 계산에는 시계가 끼어들지 않는다.

**다음 주로 넘기기는 연속으로 누를 때만 값이 붙는다.** 한 번은 언제나 공짜이고,
그 사이에 무엇이든 하면(돈이나 스태미나가 나가는 모든 행동 — `state._acted()`)
카운터가 0 으로 돌아간다. 값은 1 → 2 → 3 코인으로 오른다.

이 조합이 규칙인 이유:

- 공짜였을 때는 **버튼 연타가 언제나 최적**이었다. 시상식도 계약도 판매도
  달력만 밀면 굴러오고, 스태미나까지 공짜로 찼다.
- 그렇다고 매번 코인을 받으면 코인이 마른 회사가 시간을 못 흘려서
  아무것도 못 하게 된다 — 3.6 이 금지하는 막다른 길 그 자체다.
- 실시간 회복이 그 막다른 길을 없앤다. 코인이 하나도 없어도 기다리면
  기획서를 뽑고 계약을 받을 수 있고, **계약 납품은 코인 +1** 이라
  코인이 영구히 0 에 붙어 있을 수 없다.

`staminaMax` 를 8+rank 에서 10+1.05·rank 로 올린 것도 이 시계 때문이다.
상한이 낮으면 실시간 회복이 금방 천장을 치고 아무 의미가 없다. 크게 올리면
처리량이 통째로 움직인다 — 14+1.2·rank 로 올려 봤더니 5년차 출시작이
125편(기준 116~120)이 되고 금상이 18개 나왔다.

### 3.11.6 재촉과 콤보 — 자동 전투에 손이 끼어드는 자리

```js
URGE = { cool: 1.15, window: 2.6, step: 0.05, max: 0.55,
         critStep: 0.012, critMax: 0.15 }     // project.js
```

파티 카드를 누르면 그 사람의 게이지가 즉시 차고 한 방이 나간다. 연달아
성공하면 `project.combo` 가 오르고 **모두의** 한 방과 품질에 배율이 걸린다
(`comboMult`). 2.6초 안에 다음 재촉이 없으면 식는다.

세 가지가 이걸 "자동 전투의 대체" 가 아니라 **가속**으로 묶어 둔다:

- 재촉으로 나간 한 방도 그 사람의 체력을 정상적으로 먹는다. 연타는 팀을
  갈아 넣는 행동이다.
- 사람마다 쿨다운(1.15초)이 있다. 한 명만 계속 두들길 수는 없다.
- 배율에 상한(+55%)이 있다. 없으면 손가락이 빠른 사람이 밸런스를 벗어난다.

밸런스 시뮬레이션은 재촉을 쓰지 않으므로 `tools/balance.mjs` 의 수는
이 시스템을 넣기 전과 **완전히 같다**. 그게 의도다 — 콤보는 잘 두는 AI 의
곡선이 아니라 사람의 손끝을 위한 것이다.

### 3.11.7 경쟁사와 주간 판매 차트

`game/rivals.js`. 라이벌 셋이 각자의 속도로 게임을 내고, 우리 운영작과 같은
표에서 유저 수로 줄을 선다. 라이벌의 규모는 **우리 최고작의 유저 수**를
따라간다 (`marketScale`) — 고정 숫자로 두면 1년차에는 넘볼 수 없는 벽이고
5년차에는 아무도 아니다.

1위를 지킨 주에는 팬이 는다 (`CHART_FAN_BONUS = 0.06` × 1위 유저 수).
차트가 숫자로만 존재하면 아무것도 바꾸지 않는 장식이 되기 때문이고,
그렇다고 크면 "잘 만드는 방법" 이 되어 버리므로 작다.

### 3.11.8 도우미

`game/helpers.js`. 코인 5로 뽑고, 랭크가 여는 자리(1 → 5랭크에 2 → 12랭크에 3)
만큼 낀다. 겹쳐 뽑으면 레벨이 오르고 효과가 세진다.

**효과는 작아야 한다.** 도우미가 팀보다 세지면 게임은 직원을 키우는 것이
아니라 뽑기를 돌리는 것이 된다. 그래서 한 마리는 한 자릿수 퍼센트이고,
합계에도 천장이 있다 (`helperBonus` 끝의 clamp — 한 방 ×1.8, 기획 ×1.6,
상자 ×3.0, 번뜩임 +20%p).

들어가는 자리는 `ctx().helpers` 하나다. 없으면 전부 1 이라 예전과 완전히
같은 수가 나오고, 그래서 밸런스 시뮬레이션은 이 시스템을 안 본다.

### 3.12 달력 위의 정기 행사

| 행사 | 주기 | 여는 곳 | 주는 것 |
|---|---|---|---|
| 시상식 | 매달 1주 | `state._runAwards()` | 부문별 상금·코인·팬. 상금은 즉시 입금되고 결과창은 설명일 뿐이다 |
| 게임덱스 | 두 달(홀수 달) | `state._openExpo()` | 부스 방문자 → 팬 + `company.buff` (몇 주짜리 DL 배율) |
| 유저 편지 | 매주 굴림 | `state._rollFanMail()` | 게임당 3통까지. 소모품·코인·팬 |
| DL 기념비 | 누적 DL 자릿수 | `state.addDl()` | `DL_MARKS` 의 상금. 자릿수마다 한 번 |

**시상식 기준선은 곱셈이 아니라 포화 곡선이다** (`awards.awardBar`).
1.42배씩 곱해 올리던 동안 5년차 기준선이 528점이 되어 아무도 못 받았다 —
`tools/balance.mjs` 를 보면 게임의 평균 품질은 2년차에 300 근처로 올라간 뒤
그 언저리에 머문다. 지금은 `45 + 300·(1 − e^{−(y−1)/1.5})` 이고, 5년 실행에서
동상 22 · 은상 17 · 금상 1 이 나온다 (`node tools/balance.mjs` 마지막 줄).
기준선을 건드렸으면 그 숫자를 다시 볼 것.

**게임덱스 버프는 `tickRelease(rel, rnd, boost)` 로 들어간다.** 유저에는
그대로, 매출에는 절반만 걸린다 — 사람이 몰린다고 객단가까지 오르지는 않는다.
기본값이 1 이라 버프가 없으면 예전과 완전히 같은 수가 나온다.

**편지함은 넘쳐도 선물을 버리지 않는다.** `MAIL_CAP` 을 넘기면 수령·잠금이
안 된 편지부터 지우고, 두 배를 넘기면 가장 오래된 편지의 선물을 **대신
받아 주고** 지운다.

| **한 픽셀의 NaN 이 화면에 검은 사각형으로 번짐** | 도시 지오메트리를 넣자 광장 위에 화면축에 정렬된 **검은 사각형**이 떴다. 지오메트리도 색도 AO 도 그림자도 멀쩡했다 — 원인은 셰이더 안의 `normalize(0)` 이다. NaN 한 픽셀이 블룸의 다운샘플/업샘플을 타고 **밉 블록 크기의 사각형**으로 자란다. 그래서 화면축에 정렬돼 보였다. `normalize` 를 쓰는 자리마다 길이를 확인하고(`vN`, `L+V`, bumpNormal 의 결과), 마지막에 `if(!(dot(lit,lit) >= 0.0)) lit = vec3(0.0);` 로 한 번 더 막는다. **셰이더에 새 `normalize` 를 넣을 때는 인자가 0 이 될 수 있는지 반드시 볼 것** |

| 하네스가 홈화면 안내를 안 닫음 | `#a2hs` 는 창업 직후 화면 전체를 덮는다. `page.evaluate(... .click())` 은 통과하지만 **CDP 로 쏜 진짜 터치는 전부 이 카드에 맞는다.** 터치 검사 전에 반드시 닫을 것 |
| CDP 터치 상태를 안 비움 | `Input.dispatchTouchEvent` 의 접점은 세션에 남는다. 제스처마다 `touchEnd []` 로 끝내지 않으면 다음 `touchStart` 가 엉뚱한 포인터로 오거나 아예 안 온다 |
| **비동기 소환을 "지금 있나" 로만 막음** | `ensureBoss` 가 `if (this.boss && ...) return` 이었다. 모델이 네트워크에서 오는 동안 `this.boss` 는 null 이고 `playBattle` 은 초당 스무 번 여기를 지나가므로, 스테이지마다 `spawnBoss` 가 **세 번** 떴다(계측으로 확인). 늦게 온 쪽이 앞의 것을 `dispose` 없이 덮어써서 SkinnedInstance 가 스테이지마다 두 개씩 GPU 에 남았고 세트장도 그만큼 다시 지어졌다. **"지금 있나" 가 아니라 "지금 부르는 중인가"(`bossWant`/`bossLoading`) 를 볼 것** |
| 화면의 보스를 열 몇 군데에서 세우고 지움 | 어느 한 경로가 어긋나면 끝난 판 위에 보스가 남거나 다시 선다. 지금은 `update()` 가 매 프레임 불변식을 강제한다 — **화면의 보스는 지금 공정의 놈이거나 아무도 아니다**(죽는 중인 놈만 예외). 경로를 하나씩 맞추는 것보다 싸고 확실하다 |
| 세트장 카메라 거리를 몬스터 키에 비례시킴 | 세트장은 **고리**다. 브레인스토밍 광장은 반지름 22 에 화이트보드가 둘러서 있고 기본 거리 21 은 그 안쪽에 카메라를 두려고 고른 값이다. 7.4 유닛짜리 외계 사양에 맞춰 28 로 물렸더니 카메라가 보드 밖으로 나가 화면이 통째로 판때기가 됐다. **거리는 줄이기만 한다**(`arenaDist` 의 상한 1.0); 큰 놈은 `arenaTarget` 의 시선 높이로 담는다 |
| 튜토리얼 단계에 끝낼 방법이 없음 | '선물을 주세요' 는 선물이 손에 없으면 영원히 안 지워졌다(상점에서 사거나 상자에서 나와야 하는데 둘 다 안 나올 수 있다). 새 단계를 넣을 때 **`done(g)` 이 반드시 참이 될 수 있는지** 볼 것. 안 되면 건너뛸 조건을 같이 넣는다 (`loot`·`helper` 단계가 그렇게 한다) |
| 무대를 몬스터 id 로 고름 | 종족이 제비뽑기로 정해지면 같은 공정이 매번 다른 장면이 되고, "지금 어느 공정인가" 를 화면에서 읽을 수 없다. **무대는 공정의 것**(`stage.set`), 몸만 뽑는다 |

## 5. 테스트 하네스 (`tools/`)

### 브라우저 불필요 — 밸런스 · 에셋

```bash
node tools/balance.mjs [시드] [연차]   # 잘 두는 AI, 기본 12345 5
node tools/sloppy.mjs  [시드]          # 최악의 플레이, 파산 방지선 검사
node tools/monster.mjs                 # 보스 에셋: 스킨·클립·조인트·NaN 검사
```

`balance.mjs` 는 연차별 표(랭크·자금·팬·출시작·평론가·평균품질·레벨·
명예의 전당·직급분포)와 초기 20작의 `x` / 품질 / 평론 추이를 찍는다.
**밸런스를 건드렸으면 최소 3개 시드로 돌려볼 것.** 한 시드는 거짓말을 한다.

두 시뮬레이션 모두 이제 **가구를 사서 놓는다.** 사무실이 비어서 시작하니
책상 없이는 채용이 안 되고, 채용이 안 되면 아무것도 측정할 수 없다.
`clearOfWalls` 는 `() => true` 로 스텁이다 — 그 검사에는 WebGL 이 만든
충돌 격자가 필요하고, 배치 구역 검사만으로도 헤드리스에서는 충분하다.

`monster.mjs` 는 `core/gltf.js` 의 스켈레톤 솔버가 순수하기 때문에
브라우저 없이 돈다. 클립을 한 프레임씩 밟으면서 조인트 행렬이 유한한지,
실제로 움직이는지, 정점이 참조하는 조인트 번호가 범위 안인지 본다.
**`.glb` 를 다시 만들면 이걸 먼저 돌릴 것.**

```bash
node tools/gltf2glb.mjs in.gltf out.glb Idle,Walk,Punch,HitReact,Death
```

`.gltf`(base64 내장) → `.glb` 재포장 + 안 쓰는 클립 제거. 오크 기준
1.25MB → 425KB. 몬스터 팩은 클립 14개를 싣고 오는데 게임은 5개만 쓴다.

### 브라우저 필요

```bash
(setsid python3 -m http.server 8123 &)      # setsid 중요
node tools/probe.mjs      # 부팅만 (에러/단계별 타이밍/월드 통계)
node tools/meeting.mjs    # 창업·가구·채용 → 경로탐색 → 회의 → 착석 → 복귀
node tools/flow.mjs       # 전체 플로우 + 배치 조작 + 세이브 이관 42개. 지금 42/42 통과
node tools/battle.mjs     # 상점·소재 뽑기·장비·체력·도감·1인칭 26개
node tools/raid.mjs       # 보스 아레나 3연전·세트장·판매 패널 11개
node tools/shots.mjs      # 눈으로 볼 것들의 스크린샷 (CI 아님)
node tools/features.mjs   # 채용·퇴사 연출, 기획서 폐기, 디버그 점수, 품질 막대,
                          # 미발견 조합, 주간 이벤트, 세일즈 태스크, 1인칭
                          # ⚠ 현재 6/19 통과 — 하네스가 낡았다 (아래)
```

`battle.mjs` 는 1인칭을 **방향까지** 검사한다. 스틱이 도는지가 아니라
미는 쪽으로 실제로 가는지, 시선을 돌리면 전진 방향도 도는지, 벽에서 멈추는지를
본다 — "1인칭이 이상하게 간다" 는 셋 중 하나가 깨진 것이다.

`flow.mjs` 의 **3-b 절**은 CDP 로 진짜 멀티터치를 쏜다. 배치 중에 손가락
두 개로 끌었을 때 `cam` 의 az/el/거리/타깃이 **한 톨도** 안 움직이는지가
검사의 전부다 — 그 계약이 깨졌던 것이 "책상을 옮기려는데 화면이 움직인다"
의 정체였다. 같은 절에서 십자 버튼이 정확히 반 칸을 옮기는지, 조이스틱이
배치 중에도 카메라를 돌리는지도 같이 본다.

`raid.mjs` 는 **배선**만 본다. 규칙은 node 로 돌릴 수 있고 이미 돌렸다.
브라우저에서만 깨지는 것은 rAF 루프가 `devTick` 을 부르는가, 스테이지가
넘어갈 때 3D 보스가 바뀌는가, 카드 팝업이 전투를 막았다가 풀어주는가,
그리고 화면이 정말 바뀌는가다.

> **`features.mjs` 는 지금 6/19 만 통과한다.** 게임이 아니라 **하네스가**
> 낡았다 — UI 가 바뀌면서 첫 몇 단계가 어긋나고, 그 뒤가 줄줄이 무너진다
> (없는 프로젝트에서 `criticTotal` 을 읽는 식). 같은 실패가 이 작업 **이전**
> 커밋에서도 그대로 나온다는 것을 확인했으므로 회귀가 아니다. 여기서 보던
> 것들은 대부분 `flow.mjs` · `battle.mjs` · `raid.mjs` 로 옮겨갔다. 손볼
> 사람은 첫 실패부터 고칠 것 — 뒤의 실패는 전부 그 그림자다.

환경변수: `PLAYWRIGHT=` (기본 `/opt/node22/.../playwright/index.mjs`),
`PORT=` 또는 `BASE=`, `OUT=` (스크린샷 저장 위치).

`flow.mjs` 는 실제 DOM 컨트롤을 눌러서 렌더 경로가 깨지면 소리를 낸다.
게임 객체는 "한 시간 플레이해야 도달하는 상황"(랭크·자금) 을 만들 때만 쓴다.
SwiftShader 가 느리므로 **고정 딜레이 대신 상태를 폴링**하도록 짜여 있다.

`flow.mjs` 마지막에 `flow-final.png` 가 떨어진다. 렌더링이 눈으로 멀쩡한지
확인할 때 쓸 것. `features.mjs` 는 단계마다 스크린샷을 남긴다 (`01-a2hs.png`
… `06-back.png`).

`tools/` 하네스는 `tools/` 이름을 README 의 구조 목록에도 넣어둔다.

`shots.mjs` 는 **숫자로 검사할 수 없는 것**을 위한 것이다. 스킨드 몬스터는
조인트가 전부 유한하고 올바른 클립이 돌고 GPU 에 메시가 올라가 있어도
안팎이 뒤집혔거나, 열 배 크거나, 남의 팔꿈치로 텍스처링돼 있을 수 있다.
창업 화면 · 빈 사무실 · 배치 모드 · 가구 놓은 사무실 · 몬스터 3종 ·
전투 UI · 사무실 패널을 PNG 로 떨군다.

## 6. 배포

Vercel 정적 배포. 빌드 스텝이 없다.

```bash
npx vercel --prod
```

- `vercel.json` 은 캐시 헤더만 정한다. `sw.js`/`src/` 는 매번 재검증.
- **`sw.js` 에 파일 두 개를 챙겨야 한다**: `ASSETS` 목록에 새 모듈 추가 +
  `CACHE` 버전 올리기 (현재 `sds3d-v3`). 안 하면 업데이트가 안 퍼진다.
- `assets/monsters/*.glb` 는 **일부러 프리캐시하지 않는다.** 셋이 합쳐
  1MB 에 가깝고 프로젝트당 한 종만 나오므로, 런타임 fetch 핸들러가
  처음 쓸 때 캐시한다. 첫 실행이 가벼워지고 두 번째부터는 즉시 뜬다.
- 서비스 워커는 HTTPS 에서만 등록되므로 로컬에서는 오프라인 캐시가 꺼진다.

목록이 최신인지 확인:

```bash
ls src/*/*.js src/*.js | sed 's|^|"./|;s|$|",|' | sort   # sw.js 의 목록과 비교
```

## 7. 다음에 할 만한 것

머지를 거치며 이 목록에 중복이 쌓여 있었다 (사운드가 세 번, 랜덤 이벤트가

1. **시설 배치** — 층마다 시설 슬롯(서버랙/사운드부스/휴게실/회의실 확장).
   `world/office.js` 는 이미 방을 rect 로 잡고 있으니 슬롯을 데이터로 빼고
   `game/state.js` 에 구매 액션을 붙이면 된다. 원작의 큰 축인데 지금은
   층 역할(`FLOOR_PLANS[].role`)만 있다.
2. **자체 플랫폼 개발** — 랭크 20 해금 플랫폼은 있는데 "개발" 과정이 없다.
   `data.js` PLATFORMS 의 `own` 을 목표로 하는 별도 트랙.
3. **직원이 가구를 쓰게 하기** — 지금 쾌적도는 숫자로만 작동한다.
   `world/agents.js` 의 ambient 스폿을 플레이어가 놓은 소파·커피머신에서
   생성하면 좋은 사무실이 눈에 보이게 된다. `placed.js` 가 이미 위치를
   알고 있으므로 `out.spots` 를 하나 더 내보내면 끝이다.
4. **보스가 실제로 반격** — 지금 반격은 버그를 얹는 것까지다. 턴을 되돌리는
   식의 수치를 더 붙이려면 `game/project.js` 의 `bossAttack` 안에서 해야
   한다 (`world/boss.js` 는 규칙을 몰라야 한다).
5. **속편/시리즈 UI 다듬기** — 로직은 있다(`seriesOf`, `seriesN`).
   명예의 전당 목록에서 바로 속편을 만들 수 있게.
6. **후반 성장** — 지금 `x` 가 ~450 에서 정체한다. 환생(재능 ×1.12)이 유일한
   돌파구인데 UI 유도가 약하다. 10년 넘게 가는 세이브를 원하면 여기가 병목.
7. **1인칭 확장** — 지금은 걷기 + 격려 + 비품 한 마디까지다. 다음 수는
   책상 앞에서 그 사람의 상세 패널 열기(3D 이름표는 이미 그렇게 열린다),
   회의실에서 회의 소집, 사장 아바타.
8. **경쟁사 확장** — 지금 라이벌은 차트에만 산다. 라이벌의 신작이 우리
   유행을 흔들거나, 같은 장르로 맞불을 놓거나, 스카우트를 시도하는 쪽으로
   갈 수 있다. `game/rivals.js` 한 파일에서 끝난다.

   옆에 스케줄러가 하나 붙어야 한다 (`AudioContext.currentTime` 기반 lookahead).

## 9. 에셋

`assets/monsters/*.glb` 는 **Quaternius** 의 CC0 몬스터 팩에서 왔다
(원본 아틀라스 이름 `Atlas_Monsters`, Blender glTF 익스포터 v1.7.33).
클립 14개 중 게임이 쓰는 5개만 남기고 `tools/gltf2glb.mjs` 로 재포장했다.

`assets/furniture/kit.json` (수입 가구), `assets/city/kit.json` (창밖 건물),
`assets/city/cars.json` (길 위의 차) 는 **Kenney** 의 CC0 팩에서 왔다:
Furniture Kit · City Kit Commercial 2.1 · Car Kit 3.1. 셋 다
`tools/kit.mjs` 가 OBJ 에서 삼각형만 뽑아 이 게임의 지오메트리 포맷으로
재포장한 것이다.

```bash
node tools/kit.mjs furniture "<팩>/Models/OBJ format" assets/furniture/kit.json
node tools/kit.mjs city      "<팩>/Models/OBJ format" assets/city/kit.json
node tools/kit.mjs car       "<팩>/Models/OBJ format" assets/city/cars.json
```

**색이 오는 길이 팩마다 다르다.** Furniture Kit 은 머티리얼마다 Kd(확산색)를
들고 오지만, City/Car Kit 은 머티리얼이 `colormap.png` 한 장뿐이고 색은 UV 가
가리키는 아틀라스 칸에 있다. 그래서 `kit.mjs` 는 **PNG 를 직접 디코딩해서
(zlib 만 씀 — 의존성 없음) 삼각형마다 한 색으로 구워 넣는다.** 결과 json 에는
여전히 색과 머티리얼 id 만 남고, 게임은 텍스처를 한 장도 싣지 않는다.
색은 12단위로 뭉갠다 — 그러지 않으면 아틀라스의 얕은 그라데이션 때문에
택시 한 대가 120개 파트로 쪼개진다.

**저폴리 쪽을 쓴다.** City Kit 은 같은 건물을 `building-*`(2,200~10,500 삼각형)
과 `low-detail-building-*`(124~756) 두 벌로 싣고 온다. 창밖 200 유닛 밖의
실루엣에 만 단위 삼각형을 쓰는 것은 폰에서 그대로 프레임이므로, 기본은
저폴리이고 길 건너 랜드마크 두 채만 제대로 된 모델이다. 도시 전체가
2만 5천 삼각형이고, 1층짜리 사무실 전체(약 1만 2천)의 두 배쯤이다.

어떻게 배선하는지는 [ASSETS.md](ASSETS.md) 에 따로 적었다.**
