## 0. 30초 요약

카이로소프트 **소셜게임 스토리**를 의존성 없는 WebGL2 3D로 옮긴 리메이크.
**모바일 가로 모드 전용**, Vercel 정적 배포, PWA.

```bash
python3 -m http.server 8123     # 빌드 스텝 없음. ES 모듈이라 정적 서버만 필요
node tools/balance.mjs 12345 10 # 밸런스 시뮬레이션 (브라우저 불필요)
node tools/flow.mjs             # 전체 플로우 브라우저 테스트 (19개 검사)
```

한 바퀴가 전부 돈다: 기획서 → 회의 → 개발 배틀 → 아이디어 카드 →
완성 → 디버그 → 홍보 → 출시 → 운영 → 팬 → 랭크 → 층 구매 → 다시.
저장/불러오기, 직원 육성·전직·환생·특성, 연구·계약·유행까지 들어가 있다.

## 1. 파일 지도

```
src/
  core/     math gl color meshbuilder bake        순수 유틸. 게임도 렌더도 모름
  render/   shaders renderer camera               PBR 파이프라인
  char/     rig poses                             16본 스켈레톤
  world/    palette props office agents           지오메트리 + 직원 상태 기계
  game/     data state staff project economy dialogue   순수 시뮬레이션 (DOM/WebGL 없음)
  ui/       hud device style.css                  DOM 오버레이
  main.js                                         셋을 묶는 View + 부트스트랩
tools/      balance sloppy flow meeting probe     테스트 하네스 (아래 5장)
```

**경계가 이 프로젝트의 전부다.** `game/` 이 DOM 을 모르기 때문에 밸런스를

**`game/` 안에 `document`, `window`, `canvas` 를 절대 들이지 말 것.**
(`localStorage` 는 `state.js` 의 save/load 에만 있고 try/catch 로 감싸져 있다.)

## 2. 반드시 알아야 할 규약

### 2.1 좌표와 방향 — 여기서 버그가 네 번 났다

- **−Z 가 북쪽.** rig 가 yaw `y` 면 바라보는 방향은 `(sin y, cos y)`.
- **의자 회전은 `yaw − PI/2`.** 좌석은 `yaw` 하나만 들고 다니고 가구
  회전은 거기서 유도한다. 두 숫자를 따로 두면 사람이 뒤돌아 앉는다.
- **`props.js` 에서 무언가를 "옆으로" 밀 때는 `(sin ry, cos ry)` 를 쓴다.**
  `(cos, sin)` 을 쓰면 90° 틀어진다. 실제로 이 실수로:
  - 책상 가림판이 앞이 아니라 **옆면**에 서서 5유닛 벽이 됐고,
  - 문틀 기둥이 벽과 나란하지 않고 **자기 문을 가로막았고**,
  - 계단이 엘리베이터 코어에서 **옆으로 13유닛 뻗어나갔다**.

  새 프롭을 추가하면 `tools/flow.mjs` 가 아니라 **경로 탐색 테스트**
  (`tools/meeting.mjs` 의 첫 검사)로 확인할 것. 벽이 생기면 즉시 잡힌다.

### 2.2 NavGrid 는 area 를 반드시 받는다

`core/bake.js` 의 `new NavGrid(mesh, y0, y1, cell, dilate, area)` —
**`area` 를 생략하면 안 된다.** 메시에는 광장과 스카이라인까지 들어 있어서,
격자가 거기에 맞춰 자기 크기를 잡고 셀 예산(900×900)에 맞추려고 조용히
해상도를 낮춘다. 그러면 `path()` 가 `no route` 를 뱉는다.
지금은 예산 초과 시 **throw** 하도록 해놨으니 조용히 망가지지는 않는다.

층마다 격자가 따로다. 하나로 합치면 모든 층의 가구가 한 장으로 융합돼
전부 막힌다 (`main.js` `build()` 참조).

### 2.3 돌하우스 컷

두 종류가 동시에 돈다.

1. **벽 디더 컷** — 카메라와 시점 사이의 벽이 4×4 오더드 디더로 녹는다.
2. **층 컷** — 보고 있는 층 위쪽이 통째로 잘린다.
   `floorY = view.floor * STOREY + BUILDING.wallH + 0.1`, 램프 0.7.

플래그는 `world/office.js` 의 `buildSite()` 안에 세 종류가 있다.

| 플래그 | 뜻 | 쓰는 곳 |
|---|---|---|
| `0` | 두 컷 모두 적용 | 실내 벽·가구 |
| `3` | 벽 컷만 면제 | 외부 기둥, 파라펫 — 얇아서 디더로 녹여봐야 얼룩만 생긴다 |
| `SITE = 4` | **두 컷 모두 면제** | 지면·도로·주변 빌딩 |

**지붕을 SITE 로 하면 안 된다.** 파라펫은 `3` 이라서 아래층을 보면 같이
사라진다. 예전에 지붕을 통짜 슬래브로 덮었더니 컷 임계선 위에 걸려
화면 전체가 흰 디더가 됐다. 지금은 슬래브가 아니라 **링**이다.
새 야외 프롭을 추가하면 이 표를 보고 플래그를 고를 것.

### 2.4 회의 연출의 프레임 독립성

`main.js` 의 프레임 루프는 `dt` 를 **0.1초로 클램프**한다. 저사양 기기에서
2fps 가 나오면 걷기가 1/20 속도가 되고 회의가 영원히 안 끝난다.
그래서 `playMeeting()` 은 **4.5초 데드라인**을 두고 `crew.forceSeat()` 으로
남은 사람을 자리에 순간이동시킨다. 회의 로직을 손대더라도 이 안전장치는
남겨둘 것 — 없으면 느린 폰에서 게임이 멈춘 것처럼 보인다.

### 2.5 층을 사면 월드를 다시 짓는다

`View.setFloorCount(n)` → `build()` 전체 재실행 (AO 굽기 + 층별 NavGrid).
폰에서 몇 초 걸리므로 `body.busy` + `#busy` 배너가 뜬다.
**`bootStep()` 은 null-safe 여야 한다** — 부트 오버레이는 이미 제거된 뒤다.
(이걸 놓쳐서 "층을 사면 돈만 나가고 아무 일도 안 일어나는" 버그가 있었다.)

## 3. 밸런스 — 지금 숫자와 그 이유

### 3.1 도달 곡선 (10년 × 5시드, `tools/balance.mjs`)

| | 랭크 | 출시작 | 평론가 | 명예의 전당 |
|---|:-:|:-:|:-:|:-:|
| 1년차 | 2~3 | 6 | 11~15 | 0 |
| 2년차 | 3~7 | 14~21 | 13~24 | 0 |
| 3년차 | 8~10 | 25~31 | 19~25 | 0 |
| 5년차 | 11~13 | 38~56 | 28~35 | **첫 등재 (0~14)** |
| 7년차 | 13~15 | 65~83 | 30~35 | 14~35 |
| 10년차 | 15~16 | 100~124 | 30~36 | 42~73 |

첫 명예의 전당(32점)이 4~5년차에 오는 건 **핵심 6명이 두 번째 전직을
마치는 시점**이라서다. 우연이 아니라 구조이므로, 전직 조건이나
`maxLevel = 30 + tier*30` 을 건드리면 이 시점이 통째로 움직인다.

### 3.2 두 개의 포화 곡선 (`game/project.js` 상단)

```js
const QCAP = 999, QSCALE = 560;   // 품질 = 999(1 - e^(-x/560))
const CBASE = 2.2, CSPAN = 7.8, CSCALE = 330;  // 평론가 1인 = 2.2 + 7.8(1 - e^(-v/330))
```

`x` = **1인·1턴당 기여**. 창업 ~10 에서 성숙기 ~450 까지 간다.
`project.rawPerSlot` 에 그대로 담아두므로 시뮬레이션에서 바로 볼 수 있다.

곡선이 반드시 포화형이어야 하는 이유: 능력치가 레벨×전직×의욕×궁합×
개발방식으로 **곱해지며** 네 자릿수를 넘어간다. 선형으로 두면 2년차에
차트를 벗어난다.

### 3.3 처리량(연간 출시작)을 결정하는 것

```
연간 출시작 ≈ 48주 × 주간 스태미나 ÷ (게임당 턴수 × 턴당 스태미나)
```

- **주간 스태미나**: `data.js` `rankInfo().staminaMax = min(38, 8 + rank)`
- **게임당 턴수**: `project.js` `hp = 8600 × 장르 × 플랫폼 × 시리즈 × 등급 × (1 + (랭크-1)×0.11)`

**랭크 계수가 핵심이다.** 회사의 턴당 데미지는 복리로 크는데 HP 는
플랫폼 사다리만큼만 커서, 이게 없으면 성숙한 스튜디오가 매주 한 작품씩
찍어낸다 (실측: 10년차 300작 → 120작). 처리량이 이상해지면 **여기부터** 볼 것.

### 3.4 팬 → 랭크

```js
RANK_UP_FANS = 900 × 2.2^(rank-1)     // data.js
fansGained  = users × 0.11 × (명예의전당 1.5) × 홍보 × 스타개발자   // economy.js
users       = pull × 26 × 플랫폼 × 수익모델 × ... × fanBoost(상한 9)
```

`fanBoost` 상한이 없으면 유저→팬→유저로 자기를 먹여 2년차에 폭주한다.

### 3.5 성장의 느린 길 (절대 막히면 안 되는 것)

- 아이템 = 빠른 길. 돈 + 스태미나(`trainStamina = 1 + level/22`)를 쓴다.
- **출시 = 느린 길.** `state._completeProject()` 에서 팀원이
  `xp = 20 + hpMax/300 + 평론×2` 를 받는다. `expToNext = 18 × level^1.15`.

이게 없으면 돈을 안 쓰는 플레이어가 **레벨 3에 영구히 묶인다**.
`tools/sloppy.mjs` 가 정확히 그 상태를 검사한다.

### 3.6 파산 방지선

`state.nextWeek()`: 자금 < −120,000 이면 스폰서가 40,000 으로 채워주고
**전 직원 의욕 −2**. 공짜가 아니어야 반복 구제가 실제로 아프다.
정상적인 탈출구는 **계약 일감**(랭크 1에 14,000~42,000).

`tools/sloppy.mjs` (연구·홍보·계약·육성 전부 무시, 카드도 첫 장) 로 8년
돌리면 파산하지 않지만 유저가 바닥(400명)에 붙어 랭크 1에 머문다.
**"죽지는 않되 아무것도 나아지지 않는" 상태가 설계된 하한선이다.**

### 3.7 버그 개수

```js
scale = 8 + 12 × log2(1 + hpMax/4500);   bugs = scale × (1.5 − min(1.2, 조작성/70))
```

HP 에 **선형이면 안 된다.** 예전에 중반 프로젝트에 163개가 붙었고,
디버그 스무 번은 선택이 아니라 노가다였다. 지금은 중앙값 12~16개,
디버그 1~2회. 조작성이 실제로 개수를 줄이는 게 이 식의 요점이다.

## 4. 알려진 함정 (다음 사람이 또 밟을 것들)

| 함정 | 실제로 일어난 일 |
|---|---|
| `bootStep()` 이 부트 오버레이 제거 후 throw | 층을 사면 돈만 나가고 월드가 조용히 그대로. **now null-safe** |
| NavGrid 에 `area` 미지정 | 격자가 스카이라인까지 덮고 해상도가 낮아져 `no route` |
| `props.js` 에서 `(cos, sin)` 사용 | 가구가 90° 틀어져 통로를 막는 벽이 됨 |
| 옥상을 통짜 슬래브로 덮음 | 층 컷 임계선 위에 걸려 화면 전체가 흰 디더. 지금은 파라펫 **링** |
| 모달 클래스는 `.show` 다 (`.hide` 아님) | 테스트에서 모달 감지가 반대로 돌아 배틀 루프가 무한정 |
| `confirm()` 은 `#mOk` 가 아니라 `#mOpts .choice` | "예" 를 클릭해야 한다. `mOk` 는 `display:none` |
| 완성작 패널은 **개발 탭**에 있다 (운영 아님) | `panelDev()` 가 `g.finished` 면 `panelFinished()` 로 분기 |
| 테스트에서 `.item.click` 을 먼저 찾으면 | 직원 카드가 자식 버튼의 텍스트를 포함해서, 버튼 대신 카드가 눌려 패널이 접힌다. **버튼 먼저 검색** |
| 900px 이상 뷰포트에서 패널이 접혀 시작 | 테스트는 `body.classList.remove('panel-hidden')` 로 명시적으로 열 것 |
| SwiftShader 에서 1~2fps | 소프트웨어 래스터라이저 + DPR 2 + 5단 블룸. **실기기 문제 아님.** 테스트는 딜레이 대신 폴링할 것 |
| 서버가 프로세스 그룹 종료로 죽음 | `setsid` 로 띄울 것 |

## 5. 테스트 하네스 (`tools/`)

### 브라우저 불필요 — 밸런스

```bash
node tools/balance.mjs [시드] [연차]   # 잘 두는 AI, 기본 12345 5
node tools/sloppy.mjs  [시드]          # 최악의 플레이, 파산 방지선 검사
```

`balance.mjs` 는 연차별 표(랭크·자금·팬·출시작·평론가·평균품질·레벨·
명예의 전당·직급분포)와 초기 20작의 `x` / 품질 / 평론 추이를 찍는다.
**밸런스를 건드렸으면 최소 3개 시드로 돌려볼 것.** 한 시드는 거짓말을 한다.

### 브라우저 필요

```bash
(setsid python3 -m http.server 8123 &)      # setsid 중요
node tools/probe.mjs      # 부팅만 (에러/단계별 타이밍/월드 통계)
node tools/meeting.mjs    # 경로탐색 → 회의 시작 → 착석 → 말풍선 → 복귀
node tools/flow.mjs       # 전체 19개 검사. 지금 19/19 통과
```

환경변수: `PLAYWRIGHT=` (기본 `/opt/node22/.../playwright/index.mjs`),
`PORT=` 또는 `BASE=`, `OUT=` (스크린샷 저장 위치).

`flow.mjs` 는 실제 DOM 컨트롤을 눌러서 렌더 경로가 깨지면 소리를 낸다.
게임 객체는 "한 시간 플레이해야 도달하는 상황"(랭크·자금) 을 만들 때만 쓴다.
SwiftShader 가 느리므로 **고정 딜레이 대신 상태를 폴링**하도록 짜여 있다.

`flow.mjs` 마지막에 `flow-final.png` 가 떨어진다. 렌더링이 눈으로 멀쩡한지
확인할 때 쓸 것.

## 6. 배포

Vercel 정적 배포. 빌드 스텝이 없다.

```bash
npx vercel --prod
```

- `vercel.json` 은 캐시 헤더만 정한다. `sw.js`/`src/` 는 매번 재검증.
- **`sw.js` 에 파일 두 개를 챙겨야 한다**: `ASSETS` 목록에 새 모듈 추가 +
  `CACHE` 버전 올리기 (현재 `sds3d-v2`). 안 하면 업데이트가 안 퍼진다.
- 서비스 워커는 HTTPS 에서만 등록되므로 로컬에서는 오프라인 캐시가 꺼진다.

목록이 최신인지 확인:

```bash
ls src/*/*.js src/*.js | sed 's|^|"./|;s|$|",|' | sort   # sw.js 의 목록과 비교
```

## 7. 다음에 할 만한 것

우선순위 순. 전부 "지금 구조에서 자연스럽게 이어지는" 것들이다.

1. **시설 배치** — 층마다 시설 슬롯(서버랙/사운드부스/휴게실/회의실 확장).
   `world/office.js` 는 이미 방을 rect 로 잡고 있으니 슬롯을 데이터로
   빼고 `game/state.js` 에 구매 액션을 붙이면 된다. 원작의 큰 축인데
   지금은 층 역할(`FLOOR_PLANS[].role`)만 있다.
2. **랜덤 이벤트** — 주간 클록(`state.nextWeek()`)에 훅. 서버 다운,
   유명인 트윗, 경쟁사 출시, 직원 번아웃. 유행 시스템과 같은 자리에 붙는다.
3. **자체 플랫폼 개발** — 랭크 20 해금 플랫폼은 있는데 "개발" 과정이 없다.
   `data.js` PLATFORMS 의 `own` 을 목표로 하는 별도 트랙.
4. **속편/시리즈 UI 다듬기** — 로직은 있다(`seriesOf`, `seriesN`).
   명예의 전당 목록에서 바로 속편을 만들 수 있게.
5. **사운드** — 지금 완전 무음. 클릭/크리티컬/출시 정도만 있어도 크다.
   WebAudio 로 절차적 생성하면 에셋 파일 없이 갈 수 있다 (프로젝트 원칙 유지).
6. **후반 성장** — 지금 `x` 가 ~450 에서 정체한다. 환생(재능 ×1.12)이
   유일한 돌파구인데 UI 유도가 약하다. 10년 넘게 가는 세이브를 원하면
   여기가 병목이다.

### 손대지 말아야 할 것

- **`game/` 에 DOM 을 들이는 것.** 밸런스 시뮬레이션이 죽는다.
- **텍스처 파일 추가.** 모든 표면이 프로시저럴 머티리얼 16종이다.
  이게 이 프로젝트의 기술적 정체성이고, 하나 넣으면 둑이 터진다.
- **의존성 추가.** `npm install` 없이 도는 것이 요구사항이다.
