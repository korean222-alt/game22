# 소셜게임 스토리 3D — 게임 개발 계획서

원작 `소셜게임 스토리`(Kairosoft, Social Dev Story)의 2D 도트 경영 시뮬레이션을
**실시간 3D**로 옮긴다. 리서치 근거는 [RESEARCH.md](./RESEARCH.md).

---

## 0. 무엇을 만드는가

> 당신은 오늘부터 사장님이다.
> 층층이 쌓인 사무실에 직원을 앉히고, 기획서를 뽑고,
> **아이디어와 싸워** 게임을 완성하고, 출시해서 유저를 모은다.

- 픽셀 아이소메트릭 → **WebGL2 PBR 렌더링**
- 2D 스프라이트 직원 → **16본 스켈레톤 리깅 캐릭터**
- 평면 사무실 → **층을 쌓아 올리는 3D 오피스 타워**
- 개발 진행 바 → **보스 아레나 3연전을 3D 사무실에서 눈으로 본다** (자동 전투)

## 1. 기술 스택

| 항목 | 선택 | 이유 |
|---|---|---|
| 렌더러 | 직접 짠 WebGL2 | 의존성 0, 프로시저럴 머티리얼로 텍스처 에셋 불필요 |
| 모듈 | 네이티브 ES Modules | 빌드 스텝 없음. 정적 서버만 있으면 실행 |
| 상태 | 순수 JS 객체 + localStorage | 세이브가 곧 JSON |
| UI | DOM 오버레이 | 3D 캔버스 위에 얹는 편이 텍스트가 선명함 |
| 언어 | 한국어 우선 | 원작 한국어판 기준 |

빌드 툴체인을 두지 않는 것이 의도적인 선택이다. `python3 -m http.server` 하나면 돈다.

## 2. 그래픽 — "더 사실적으로"

기반이 된 Dunder Mifflin 3D 엔진은 **Blinn-Phong + LDR**이었다.
사실감을 위해 렌더 파이프라인을 통째로 교체한다.

| 항목 | 이전 | 3D판 |
|---|---|---|
| 라이팅 | Blinn-Phong | **Cook-Torrance GGX PBR** (metallic/roughness) |
| 프레임버퍼 | RGBA8 (LDR) | **RGBA16F HDR** |
| 블룸 | 없음 | **브라이트패스 + 5단 다운/업샘플 블러** |
| 그림자 | 3×3 PCF | **12탭 포아송 PCF + 회전 커널 + 슬로프 바이어스** |
| 노멀 | 지오메트리 노멀 | **프로시저럴 하이트에서 유도한 범프 노멀** |
| 앰비언트 | 반구 상수 | **하늘 irradiance + 러프니스별 스펙큘러 근사(IBL 유사)** |
| 이미시브 | 없음 | **모니터·조명이 블룸에 기여** |
| 톤매핑 | ACES | **노출 제어 + ACES + 필름 그레인 + 비네트** |
| AA | FXAA | FXAA 유지 (HDR 해소 후 적용) |

머티리얼은 여전히 **프로시저럴**이다. 텍스처 파일 없이 셰이더 안에서
카펫 섬유, 나뭇결, 브러시드 메탈, 직물, 아크릴 천장타일, 피부, 머리카락을 만든다.
PBR로 가면서 각 머티리얼이 `(albedo, roughness, metallic, emissive, bumpScale)`을 갖는다.

## 3. 게임 시스템

### 3.1 회사 상태

```
자금 (₩)   코인 (🪙)   랭크 (1~50)   스태미나 (일일 행동력)
연차/월/주  팬 수      명성          플랫폼 지식
```

랭크가 게이트하는 것: 자금 상한, 직원 정원, 의욕 상한, 해금 층수, 해금 수익모델.

### 3.2 직원

5개 기본 능력치.

```
기획 PLAN  프로그래밍 PROG  그래픽 GRAPH  사운드 SOUND  소셜 SOCIAL
```

직업별 기여 (원작 준수):

| 직업 | 화제성 | 조작성 | 임팩트 | 소셜 | 지속성 | 기획서 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| 프로그래머 | ● | ● | | | | |
| 디자이너 | | | ● | | | |
| 사운드 | ● | | ● | | | |
| 네트워커 | | | | ● | ● | |
| 기획자 | | | | | | ● |

- **의욕(Motivation)**: 1당 +0.5% 배율. 자기 기획서로 완성하면 +1. 상한은 랭크 연동.
- **성장**: 아이템 지급 → 레벨업. 비용은 받는 사람의 레벨에 비례하고 **스태미나 1**이 든다
  (육성과 개발이 같은 자원을 놓고 다투게 하려는 것). 아이템 3종 + 만렙 → **전직**.
- **최고 직급 만렙 → 환생**: 직업 변경, 보너스/레벨 리셋, 재능 배율은 유지되고 ×1.12 된다.
  (만렙은 직급별 30 / 60 / 90)

### 3.3 개발 배틀 ★ 핵심 — 보스 아레나 3연전

원작의 시그니처. 3D판에서는 개발 착수와 동시에 화면이 통째로 **보스 아레나**가
되고, **아이디어에는 몸이 있다.** 위에 보스 체력, 아래에 팀, 가운데는 3D 사무실
그대로 — 액션 RPG 의 배치다.

한 프로젝트에 보스는 **세 마리**다. 하나가 세 번 변신하는 것이 아니라, 셋이
차례로 나오고 각자 자기 체력 바를 갖는다. 한 마리를 잡을 때마다 카드를 고르고,
고른 것이 다음 놈의 이름이 된다.

| 순서 | 몬스터 | 이름의 출처 | 잡으면 |
|---|---|---|---|
| 1번 | 아이디어 냥이 | 장르 | 🗣 회의 → 게임 내용 3장 중 택 1 → **합성 팝업** |
| 2번 | 난제 오크 | 고른 내용 × 장르 | 개발 방식 3장 중 택 1 |
| 3번 | 마감 데몬 | 고른 개발 방식 | **완성** |

몬스터는 순환 통로가 교차하는 지점에 선다 — 어떤 층 도면에서도, 플레이어가
무엇을 사서 어디에 놓았든 비어 있는 것이 보장된 유일한 바닥이다.

#### 스태미나와 체력의 분리

**스태미나는 게임을 만드는 데 쓴다** — 기획서, 개발 착수, 디버그, 교육, 계약.
**보스는 직원들이 자기 체력으로 잡는다.** 이 분리가 전투 설계의 축이다.

그래서 전투에는 누를 것이 없다. 직원마다 게이지가 차고, 차면 알아서 친다.
플레이어가 하는 일은 지켜보고, 지친 사람에게 밥을 먹이고, 카드를 고르는 것이다.

```
1. 플랫폼 · 기획서 · 수익 모델 · 팀 선택
2. 개발 착수      → 개발비 + 착수 스태미나 (야심에 비례, 2~9)
3. ── 아레나 ──   버튼 없음. 실시간.
     매 프레임:
       - 직원 게이지 += dt / 공격주기(약 1.3초, 지치면 최대 1.9배 느려짐)
       - 게이지가 차면 한 방:
           데미지 = 직업기여스탯 × 의욕 × 궁합 × 방식 × 스테이지방어 × 랜덤
           같은 값이 5개 품질 축에 직업별 가중치로 누적
           크리티컬이면 "번뜩임!" + 데미지 ×2.2 · 품질 ×1.8
           본인 체력 -4.0% (이것이 전투의 유일한 자원)
       - 보스 게이지 += dt / 반격주기(스테이지별 7.6 / 5.6 / 4.4초)
         → 사양 변경 · 버그 폭주 · 납기 압박 · 응답 없음 · 리뷰 폭격 중 하나
     스테이지 전환: 새 보스가 나온 직후 3타 동안 약점 (데미지 ×1.45)
     전원 탈진: 아레나 안에서 밥을 먹이거나 다음 주로 넘긴다 (주간 회복 78%)
4. 3번 보스 HP 0 → 완성.
   품질 = (누적 기여) ÷ (실제 타격 횟수) 을 포화 곡선에 통과시킨 값.
   인원을 늘리면 개발이 빨라질 뿐 품질은 오르지 않는다.
5. 디버그 (선택) → 버그 제거, 스태미나 소모
6. 출시
```

#### 보스 체력은 팀의 세기를 따라간다

예전에는 `base(장르) × 플랫폼계수 × 시리즈계수` 로 절대값을 뽑았다. 창업 직후
직원이 없는 시작으로 바꾸자 그 식이 무너졌다 — 레벨 1 세 명이 한 턴에 20씩
때리는데 데뷔작 HP가 8,000이면 296턴이다. 실제로 그랬다.

이제 HP는 **몇 번 때리면 끝나는가**로 정한다.

```
라운드 수 = 26 × (플랫폼hp/0.62)^0.34 × 장르hp^0.55 × (0.9 + 0.1×등급) × 시리즈
            (22 ~ 62 로 제한)
세 마리 총 HP = 라운드 수 × 팀의 기대 1라운드 데미지
배분 = 24% / 32% / 44%
```

강한 팀이 사는 것은 속도가 아니라 **품질**이다. 게임 하나에 드는 시간은 데뷔작
이나 대작이나 40~100초로 비슷하고, 달라지는 것은 결과물의 점수다.

시장 규모 · 경험치 · 버그 수는 팀과 무관한 **`project.scale`**(옛 HP 식 그대로)
을 본다. 그러지 않으면 약한 팀이 만든 콘솔 게임이 강한 팀이 만든 피처폰 게임보다
작은 물건이 되어 버린다.

3D 연출: 직원 캐릭터가 자리에서 일어나 데스크를 두드리고, 말풍선으로 데미지가
튀고, 크리티컬이면 화이트보드에 아이디어가 번쩍인다.

### 3.4 출시와 운영

```
초기 유저 = f(품질 5스탯, 팬 수, 플랫폼 팬층, 수익모델)
평가      = 4인 평론가 점수 (각 1~10)
매출/주   = 유저 × ARPU(수익모델) × 지속성계수
유저 감소 = 지속성 스탯이 높을수록 완만
```

- 동시 **운영 3작품** 상한. 새 작품을 운영하려면 기존작을 서비스 종료해야 한다.
- 평론가 합계가 기준 이상이면 **명예의 전당** 등재 → 속편 제작 해금.
- 속편은 라운드 수·개발비·착수 스태미나가 모두 증가하는 대신 초기 유저가 크게 늘어난다.
- **판매 현황 패널**: 출시작은 몇 주에 걸쳐 팔리고 매주 식는다. 화면 오른쪽에
  이번 주 매출 · 유저 수 · 주차별 매출 막대 · 남은 수명이 실시간으로 뜬다.

### 3.5 사무실과 가구

**사무실은 비어 있는 채로 시작한다.** 이것이 도입부 설계의 축이다.

원래는 창업 멤버 다섯 명이 이미 앉아 있고 책상도 깔려 있었다. 그러면
첫 결정이 "기획서를 뽑는다" 가 되는데, 그건 결정이라기보다 버튼이다.
지금은 이렇게 시작한다:

```
회사 이름 → 창업 지원금 ₩180,000 → 가구점 → 배치 → 채용
```

지원금은 반올림해서 정한 숫자가 아니라 초반 지출에서 역산했다.
기본 책상 3개(27,000) + 신입 3명(약 20,000) + 피처폰 프로젝트 한
편(25,000) + 두어 달 인건비를 내고도 사무실을 사람 사는 곳으로 만들
여유가 남되, 첫 결정이 공짜가 되지는 않을 만큼.

- **책상이 곧 정원이다.** 랭크는 `staffCap` 을 올리지만 실제 채용 한도는
  놓아둔 책상 수다. 사무실과 인사를 잇는 유일한 규칙이고, 게임이 채용
  화면이 아니라 가구점에서 시작하는 이유다.
- **가구 20종**을 사면 가방에 들어가고, 배치 모드에서 바닥의 지정 구역에
  놓는다. 회전은 90° 단위, 회수는 무료. 반투명 미리보기는 **실제 가구를
  그대로** 그린다 — 별도의 상자로 표시하면 언제나 실제 크기를 속인다.
- **쾌적도**는 1인당으로 잰다. `t = 1 − exp(−(Σcomfort/인원)/7)` 이
  주간 의욕 회복 확률(×0.55)과 회사 기획력(×1+0.18t)에 붙는다.
  포화 곡선이 없으면 가장 싼 전략은 전 층을 ₩2,500 화분으로 도배하는 것.
- **기획자와 개발자를 다른 층에 두는 편이 유리**하다 (원작 팁 반영).
- 배치 가능 구역(`PLACE_ZONES`)은 층 도면이 통로로 비워둔 자리 사이의
  베이다. 벽 충돌 검사만으로는 부족하다 — 출입구와 승강기 로비는 빈
  공간이라 통과해버린다.
- 시설(M2 예정): 서버랙(지속성↑), 사운드 부스(사운드↑) 등 **효과가 큰**
  가구. 지금 가구는 쾌적도와 자리 수만 건드린다.

### 3.6 플랫폼 개발

후반 콘텐츠. 자체 소셜 플랫폼을 만들고 콘텐츠 타입을 올린다.
업그레이드는 **개발비↑ · 팬층 변동 · 아이디어 HP↑** 를 동반한다.
플랫폼 지식은 한 번에 하나씩, 가장 값진 타입의 첫 업그레이드에 쓴다.

| 2년차 | 3~7 | 14~21 | 13~24 | 0 | 팬 4천~7만 |
| 3년차 | 8~10 | 25~31 | 19~25 | 0 | 3층 입주 · 유저 20만~40만 |
| 5년차 | 11~13 | 38~56 | 28~35 | 0~14 | **첫 명예의 전당** |
| 7년차 | 13~15 | 65~83 | 30~35 | 14~35 | 4층 · 유저 100만~300만 |
| 10년차 | 15~16 | 100~124 | 30~36 | 42~73 | 팬 3천만~7천만 |

첫 명예의 전당(합계 32점)이 5년차 언저리에 오는 것은 우연이 아니라 구조다.
핵심 6명이 **두 번째 전직**을 마치는 시점이 거기이고, 그때 1인·1턴 기여가
한 단계 뛴다. "우리 베테랑들이 만든 첫 작품"이라는 서사가 수치로 붙는다.

되는 대로 두는 플레이(연구·홍보·계약·육성 전부 무시, 카드도 첫 장)로도
8년간 파산하지 않는다. 대신 유저 수가 바닥(400명)에 붙어 랭크 3에 머문다 —
**죽지는 않지만 아무것도 나아지지 않는 상태**가 설계된 하한선이다.

두 시뮬레이션 모두 이제 **가구를 사서 놓는다.** 사무실이 비어서 시작하니
책상 없이는 채용이 안 되고, 채용이 안 되면 아무것도 측정할 수 없다.
빈 사무실로 바꾼 뒤에도 1년차 성적(랭크 2, 6명, 3작, 자금 16만)은
거의 그대로였다 — 창업 멤버 다섯 명이 하던 일을 지원금이 대신한다.

조정 과정에서 드러난 여섯 가지 구조적 함정:

1. **품질을 턴수로만 나누면** 인원수에 비례해 품질이 공짜로 오른다.
   → *1인·1턴당* 기여로 정규화. 사람을 더 넣으면 속도만 빨라진다.
2. **압축 곡선이 없으면** 능력치가 레벨·전직·의욕·궁합·개발방식으로
   곱해지며 네 자릿수를 넘어간다. → 품질과 평론 점수 양쪽에 포화 곡선
   (`품질 = 999(1 - e^(-x/560))`, `평론 = 2.2 + 7.8(1 - e^(-v/330))`).
3. **팬 배율에 상한이 없으면** 유저→팬→유저로 스스로를 먹여
   2년차에 차트를 벗어난다. → 상한 9배.
4. **아이디어 HP가 랭크를 무시하면** 회사의 턴당 데미지는 복리로 크는데
   HP는 플랫폼 사다리만큼만 커서, 성숙한 스튜디오가 매주 한 작품씩 찍어낸다.
   → HP에 랭크 계수를 곱한다. 10년차 출시작이 300작이 아니라 120작이 되는 이유.
5. **성장 경로가 아이템 하나뿐이면** 돈을 안 쓰는 플레이어가 레벨 3에 영구히
   묶인다. → 출시할 때마다 팀원이 경험치를 얻는다. 아이템이 빠른 길,
   출시가 느린 길이고, 느린 길은 절대 막히지 않는다.
6. **구제 금액이 게임 한 편 값보다 작아지면** 회사가 살아는 있는데 아무것도
   못 하는 상태가 된다. 파산과 똑같은 막다른 길에 절차만 하나 더 붙은 셈이다.
   → 긴급 지원금은 회를 거듭할수록 줄지만 "가장 싼 플랫폼 개발비 × 1.8 +
   주간 운영비 × 4" 아래로는 내려가지 않는다. 이건 추측이 아니라
   `tools/sloppy.mjs` 가 8년차에 실제로 그 상태에 갇혀서 생긴 항이다.

## 5. 디렉터리 구조

```
src/
  core/     math.js  gl.js  color.js  meshbuilder.js  bake.js
  render/   shaders.js  renderer.js  camera.js
  char/     rig.js  poses.js
  world/    palette.js  props.js  office.js
  game/     data.js  state.js  staff.js  project.js  economy.js
  ui/       hud.js  style.css
  main.js
```

- `core/` 는 게임을 모른다. 순수 렌더링 유틸.
- `world/` 는 게임 규칙을 모른다. 지오메트리만 만든다.
- `game/` 는 WebGL을 모른다. 순수 시뮬레이션이므로 그대로 테스트 가능하다.
- `main.js` 가 셋을 묶는다.

이 경계 덕분에 게임 밸런스를 렌더러와 무관하게 고칠 수 있다.
