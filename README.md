# 소셜게임 스토리 3D

카이로소프트의 경영 시뮬레이션 **소셜게임 스토리**(Social Dev Story)를
WebGL2 실시간 3D로 옮긴 리메이크. 의존성 없이 브라우저에서 바로 돌아간다.

> 오늘부터 사장님입니다.
> 회사 이름을 정하고, 지원금으로 **책상을 사서 배치하고**, 그 자리에
> 직원을 앉히고, 기획서를 뽑고, **아이디어 몬스터와 싸워** 게임을 만들고,
> 출시해서 유저를 모으세요.

**빈 사무실에서 시작합니다.** 창업 멤버도 책상도 없습니다.

**모바일 가로 모드 전용 게임**이다. 세로로 들면 돌려달라는 안내가 뜨고,
가로에서만 플레이된다. 홈 화면에 추가하면 PWA로 설치되어 주소창 없이
전체화면으로 뜨고 오프라인에서도 돈다.

## 실행

```bash
python3 -m http.server 8080     # 또는 npx serve
# http://localhost:8080
```

ES 모듈을 쓰므로 정적 서버가 필요하다 (`file://` 로는 열리지 않는다).
빌드 스텝도, 패키지 설치도 없다. WebGL2를 지원하는 브라우저면 된다.

외부 3D 팩(가구·도시·자동차)을 다시 뽑아야 하면:

```bash
node tools/kit.mjs furniture "<Kenney Furniture Kit>/Models/OBJ format" assets/furniture/kit.json
node tools/kit.mjs city      "<Kenney City Kit Commercial>/Models/OBJ format" assets/city/kit.json
node tools/kit.mjs car       "<Kenney Car Kit>/Models/OBJ format" assets/city/cars.json
```
서비스 워커는 HTTPS 에서만 등록되므로 로컬에서는 오프라인 캐시가 꺼져 있다.

### 카메라 조이스틱 🕹

화면 오른쪽 아래에 스틱 하나와 버튼 셋이 붙어 있다. **⟳** 를 누르면 스틱이
회전에서 **이동(✥)** 으로 바뀌고, **＋ −** 는 누르고 있는 동안 계속 확대·축소한다.

빈 바닥을 찾아 짚지 않아도 되고, 손가락이 몇 개 닿아 있든 결과가 하나뿐이다.
끄고 싶으면 **회사 탭 → 설정 → 카메라 조이스틱**.

**배치 모드에서는 캔버스가 카메라를 아예 건드리지 않는다.** 예전에는
"한 손가락은 가구, 두 손가락은 카메라" 였는데, 가로로 든 폰에서는 반대쪽
엄지나 손바닥이 화면에 닿는 순간 접점이 둘이 되어 가구 드래그가 카메라
팬으로 바뀌었다 — 화면에서는 "책상을 옮기려는데 화면이 움직인다" 로 보인다.
이제 배치 중 카메라는 조이스틱만 맡고, 툴바의 **십자 버튼**으로 반 칸씩
밀 수도 있다 (방향은 화면 기준이다).

## 게임 루프

```
회사 이름 입력 → 창업 지원금 ₩180,000
   ↓
가구점에서 책상 구입 → 가방 → 배치 모드로 바닥에 놓기
   ↓  책상 하나 = 직원 한 명. 자리가 없으면 채용이 막힌다
직원 채용 (랭크 1~2 는 신입 할인 -60%)
   ↓
기획서 뽑기 (스태미나 -1)
   ↓  장르 · ★등급이 정해진다
플랫폼 · 수익 모델 · 개발 팀 선택 → 개발비 + 착수 스태미나
   ↓
🗣 킥오프 회의 — 배정된 팀원이 자리에서 일어나 회의실로 걸어가 의견을 낸다
   ↓
⚔ 보스 아레나 — 화면이 통째로 전투가 된다
   ├ 🐱 1번 · 장르 보스   → 잡으면 🗣 회의 → 게임 내용 3장 중 택 1 → 합성 팝업
   ├ 👹 2번 · 조합 보스   → 고른 조합이 이름이 된다. 잡으면 개발 방식 3장 중 택 1
   └ 👿 3번 · 마감 데몬   → 잡으면 완성
   ▸ 직원들이 **자동으로** 친다. 버튼도 스태미나도 없다 — 줄어드는 건 직원의 체력
   ↓
완성 → 5개 품질(화제성·조작성·임팩트·소셜·지속성) + 버그 + 평론가 4인
   ↓
디버그 → 홍보 결정 → 출시 → 운영 (최대 3작품 동시, 주간 매출)
   ↓
팬 증가 → 회사 랭크 → 정원·스태미나·층 해금·플랫폼 해금
   ↓
연구 포인트 → 영구 강화 · 사무실 층 구매 · 다음 기획서
```

### 알아둘 것

- **팀 구성이 곧 품질이다.** 품질은 *1인·1턴당* 기여의 평균이다. 사람을 더
  넣으면 개발이 빨라질 뿐 품질이 오르지는 않는다. 네트워커가 없는 팀은
  소셜과 지속성이 1점에서 멈춘다.
- **의욕(Motivation)** 1당 +0.5% 배율에 크리티컬 확률까지 오른다. 자기
  기획서로 게임을 완성하면 +1.
- **기획자는 3층(기획실)에** 앉히면 기획서 등급이 오른다. 원작의
  "작가 층과 개발자 층을 분리하라"는 조언을 그대로 규칙으로 만들었다.
- **책상이 곧 정원이다.** 랭크는 상한을 올릴 뿐, 실제로 뽑을 수 있는 인원은
  놓아둔 책상 수다. 사람을 늘리려면 자리를 먼저 만들어야 한다.
- **쾌적도는 1인당으로 잰다.** 두 명 사무실에 소파 열 개는 좋은 사무실이
  아니라 창고다. 사람이 늘면 휴게 가구도 같이 늘려야 한다.
- **아이템 지급에는 스태미나가 든다.** 육성과 개발이 같은 자원을 놓고 다툰다.
- 평론가 합계 **32점 이상**이면 명예의 전당 → 속편 제작 해금. 잘 두면
  대략 **4~5년차**에 첫 등재가 나온다 — 핵심 인원이 두 번째 전직을 마치는 때다.
- **출시할 때마다 팀원이 경험치를 얻는다.** 아이템은 빠른 길, 출시는 느린 길.
  돈을 한 푼도 안 써도 성장이 멈추지는 않는다.
- **파산은 없다. 대신 긴급 지원금.** 잔고가 마이너스가 되면 팝업이 뜨고
  다시 시작할 만큼의 돈이 들어온다. 금액은 받을 때마다 줄고 직원 의욕이
  깎이지만, "가장 싼 게임 한 편 + 한 달 운영비" 아래로는 내려가지 않는다.
  그 전에 **계약 일감**을 받는 편이 언제나 싸게 먹힌다 — 스태미나만 쓰고
  의욕은 깎이지 않는다.

## 보스 몬스터 👾

세 마리를 차례로 잡는다. 어떤 놈이 나오느냐는 규모가 아니라 **몇 번째**
싸움이냐가 정한다 — 사다리 자체가 눈에 보여야 하기 때문이다.

| 순서 | 몬스터 | 이름은 누가 정하나 | 성격 |
|---|---|---|---|
| 1번 | 🐱 **아이디어 냥이** | 장르 (퍼즐 골렘, 대마왕 시나리오, 서버 리바이어던…) | 작고 만만해 보이지만 놓치면 도망간다 |
| 2번 | 👹 **난제 오크** | 방금 고른 게임 내용 × 장르 | 기획서대로는 절대 안 되는 그 부분 |
| 3번 | 👿 **마감 데몬** | 방금 고른 개발 방식 | 마감이 다가올수록 커진다 |

한 대 맞을 때마다 피격 모션과 붉은 플래시가 들어가고, 머리 위로 데미지가
뜬다. 자기 게이지가 차면 반격 모션과 도발 대사를 던지고, HP가 0이 되면
쓰러지는 연출 뒤에 다음 놈에게 자리를 내준다.

에셋은 Quaternius 의 CC0 *Ultimate Monsters* 팩을 `tools/gltf2glb.mjs` 로
다시 묶은 것이다. 자세한 것은 [docs/ASSETS.md](docs/ASSETS.md).

사무실 화면의 배틀 바에 있는 **👾 보스** 버튼으로 카메라가 몬스터를 잡고,
**⚔ 전투 화면** 으로 아레나에 들어간다.

### 세트장 — 보스마다 자기 무대가 있다 🎬

예전에는 보스가 **사무실 안**, 층 도면이 통로로 비워 둔 교차점에 섰다.
어느 층에서나 비어 있는 것이 보장된 유일한 바닥이라는 이유였는데, 화면에
나오는 그림은 "복도 한복판에 오크가 서 있다" 였다. 규칙상 안전한 자리가
연출상 엉뚱한 자리였다.

이제 아레나에 들어가면 화면이 통째로 **그 몬스터의 세트장**으로 바뀐다.

| 보스 | 무대 | 무엇이 있나 |
|---|---|---|
| 🐱 아이디어 냥이 | **브레인스토밍 광장** | 화이트보드 열 장, 포스트잇, 연필 기둥, 굴러다니는 종이 뭉치 |
| 👹 난제 오크 | **난제의 작업장** | 콘크리트 슬래브, 3단 비계, 노란 경고 띠, 안 꺼진 경광등 |
| 👿 마감 데몬 | **마감의 제단** | 갈라진 검은 제단, 붉게 새는 균열, 달력 비석 여덟, 화로 |

세트는 사무실에서 **아주 멀리 떨어진 좌표**(`ARENA_ORIGIN`)에 지어진다.
좌표가 겹치지 않으므로 사무실과 세트는 서로를 알 필요가 없고, 카메라가
어디를 보느냐가 곧 어느 장면이냐가 된다. 스테이지가 넘어가면 무대도 같이
바뀌고, 아레나에서 나오면 세트는 버려지고 보스는 사무실 자리로 돌아온다.

지오메트리는 `src/world/arena.js` 안에만 있다 — 규칙도, 카메라 조작도,
몬스터도 모른다.

## 가구와 배치 모드 🪑

**사무실은 비어 있는 채로 시작한다.** 책상은 사서 놓는 것이다.

1. **사무실 탭 → 가구점**에서 구입 (기본 책상 ₩9,000, 화분 ₩2,500…)
2. 산 물건은 **🎒 가방 탭**에 들어간다 (소모품·장비도 같은 탭이다)
3. 가방에서 **배치** 버튼 → 배치 모드. 바닥에 파란 구역이 뜬다
4. 한 손가락으로 끌어 옮기거나 툴바의 **십자 버튼**으로 반 칸씩 밀고,
   **⟳ 회전**으로 90° 씩 돌린다
5. 놓을 수 없는 자리에서는 반투명 가구가 **빨갛게** 변한다
6. **여기에 놓기**. 회수는 언제든 무료다

**배치 중 화면을 움직이려면 오른쪽 아래 조이스틱을 쓴다.** 캔버스는 통째로
가구의 것이다 — 손가락이 몇 개 닿든 카메라는 꿈쩍하지 않는다. 잡은 자리와
가구 중심의 어긋남을 기억하므로 가구가 손가락 밑으로 순간이동하지 않고,
멀리 떨어진 바닥을 짚으면 "저기로 옮겨라" 로 읽어 그 자리로 보낸다.

파란 구역은 층 도면이 통로로 비워둔 자리 사이의 **베이(bay)** 다.
1층에 책상 10개, 2~5층에 18~20개가 들어간다.

가구 **38종**이 **쾌적도**에 기여하고, 쾌적도는 유휴 직원의 주간 의욕
회복 확률과 회사 기획력에 붙는다. **1인당**으로 재기 때문에 사람이
늘면 휴게 가구도 같이 늘려야 한다.

### 수입 가구 (Kenney Furniture Kit)

절차적 박스로 쌓은 20종에 더해, **모델 가구 18종**이 있다 — 원목 책상 세트,
L자 코너 책상, 라운지 소파, 코너 소파, 간이 주방, TV 스탠드, 관엽 화분,
곰인형 같은 것들. 목록에 **수입 가구** 표가 붙는다.

GLB 를 따로 그리지 않는다. `tools/kit.mjs` 가 팩의 OBJ 를 삼각형과 정점 색으로
구워 `assets/furniture/kit.json`(173KB, gzip 36KB) 에 넣어 두고, 런타임은 그것을
사무실과 **같은 메시**에 붓는다. 그래서 벽 자르기·AO·머티리얼 셰이더가 그대로
걸리고, 텍스처는 한 장도 들어오지 않는다. 자세한 것은 `docs/ASSETS.md`.
- **자금이 마이너스로 깊어지면 스폰서가 급한 불을 꺼준다.** 공짜는 아니고
  직원 전체의 의욕이 깎인다. 그 전에 **계약 일감**을 받는 편이 싸게 먹힌다.
- **게임을 하나 완성하면 남아 있던 기획서는 전부 폐기된다.** 좋은 기획서를
  쟁여두고 몇 년을 우려먹는 길을 막는다. 매 작품마다 다시 뽑아야 한다.
- **버그는 평론가 점수를 깎는다.** 디버그로 하나씩 잡을 때마다 점수가
  올라가고, 버그를 다 잡아 32점을 넘기면 그 자리에서 명예의 전당에 오른다.
- **처음 보는 장르×소재 조합은 궁합이 `???` 로 나온다.** 한 번 만들어 봐야
  도감에 기록되고, 그 뒤부터 카드에 "환상의 조합 / 안 맞는 조합"이 보인다.
  어드벤처 × 공룡은 잘 맞고 퍼즐 × 던전은 겉돈다 — 알아내는 게 재미다.
  새 조합을 발견하면 연구 +8 · 코인 +1.
- **직전에 낸 것과 같은 조합을 또 내면 "재탕" 소리를 듣는다.** 초기 유저가
  최대 45%까지 깎인다.

## 소재 뽑기 🎁

**소재(게임 내용)는 처음부터 다 열려 있지 않다.** 판타지 · SF · 동물 · 요리 ·
학원 · 좀비 여섯 개로 시작하고, 나머지 열다섯은 상점 탭 맨 아래의
**소재 뽑기**에서 🪙 **코인 3개**로 하나씩 뽑는다. 개발 중 **게임 내용** 카드는
가지고 있는 소재 중에서만 나온다.

두 문제를 한 번에 푼다. 코인은 그동안 쌓이기만 하고 쓸 데가 없었고, 소재는
반대로 전부 열려 있어서 "만들 수 있는 것이 늘어난다"는 감각이 없었다. 붙이면
한쪽은 쓸 곳이, 다른 한쪽은 뽑을 이유가 생긴다.

코인은 **출시**(작품 규모에 따라)· **새 조합 발견**(+1) · **세일즈 태스크**로
모인다. 전부 모은 뒤에 뽑으면 연구 포인트로 바꿔 준다 — 눌러서 손해 보는
버튼은 만들지 않는다. **시장 유행**도 가지고 있는 소재 중에서만 골라진다:
뽑지도 않은 소재가 유행하면 보너스를 눈앞에 두고 손이 닿지 않는 분기가 생긴다.

기본 여섯은 어느 장르와도 두루 무난한 것들이다. 어떤 기획서를 뽑아도 카드
세 장이 채워지고 그중 하나는 쓸 만해야 하기 때문이다.

> 소재 **스포츠**는 장르 **스포츠**와 이름이 겹쳐서, 스포츠 게임의 소재
> 카드에 "스포츠"가 또 뜨는 화면이 나왔다. 소재는 장르보다 좁아야 뜻이
> 서므로 **축구**로 좁혔다. 옛 세이브의 기록(도감 · 조합 · 유행 · 출시작)은
> 불러올 때 자동으로 옮겨진다.

## 회의실 회의 🗣

**게임을 시작할 때(킥오프)와 게임 내용(소재)을 정할 때만** 배정된 팀원이
**자리에서 일어나 A\* 경로를 따라 회의실까지 걸어가** 원탁에 앉는다.
개발 방식 결정과 완성 회고는 회의 없이 바로 처리된다 — 매번 회의실에
가면 회의가 사건이 아니라 잡무가 되기 때문이다.

직군과 회의 단계에 맞는 대사가 말풍선으로 오가고, 카메라가 회의실을
잡았다가 원래 시점으로 돌아온다. 회의가 끝나야 카드 선택창이 뜬다.

연출을 끄고 싶으면 **회사 탭 → 설정 → 회의 연출 보기**.

## 1인칭 시점 🚶

🚶 버튼(또는 `F`)을 누르면 사장이 직접 사무실을 걸어 다닌다. 충돌은 직원이
쓰는 것과 **같은 보행 격자**를 쓰므로 책상과 벽을 통과할 수 없고, 층 버튼을
누르면 엘리베이터를 탄 것처럼 그 층으로 옮겨간다.

- **직원 앞에 서서 상호작용하면 격려**할 수 있다 — 의욕 +1, 사람당 주 1회.
- 커피 머신·정수기·소파·창가 자리·복합기 등 비품에도 한 마디씩 붙어 있다.
- 회의실 화이트보드는 진행 중인 프로젝트의 남은 HP를 알려준다.

## 개발 = 보스전 👾 — 3연전 자동 전투

개발 시작을 누르면 화면이 통째로 **보스 아레나**가 된다. 위에 보스의 체력,
아래에 팀, 가운데는 3D 사무실 그대로. 액션 RPG 의 배치다.

직원마다 게이지가 차고, 차면 알아서 친다. 플레이어가 하는 일은 지켜보고,
지친 사람에게 밥을 먹이고, 보스가 바뀔 때 카드를 고르는 것 — 그리고
**재촉하는 것**이다.

**보스 정보는 화면 왼쪽에 세로 기둥으로 선다.** 예전에는 위쪽에 가로로
누워 있었는데, 공정·이름·체력·완성도·점수 여섯 줄이 쌓이면서 화면의 절반이
카드가 됐다 — 보러 들어온 보스가 그 뒤에 완전히 가려졌다. 세로로 세우면
같은 정보가 폭 260px 안에 들어가고 오른쪽 3분의 2가 통째로 무대로 남는다.

| 요소 | 내용 |
|---|---|
| **3연전** | 🐱 장르 보스 → 👹 조합 보스 → 👿 마감 데몬. 셋이 각자 자기 체력 바를 갖는다. 한 마리를 잡을 때마다 카드를 고르고, 고른 것이 다음 놈의 이름이 된다 |
| **자동 전투** | 각자 약 1.3초에 한 번 친다. 지치면 느려진다 — 밥을 사주면 눈에 띄게 빨라지는 자리이고, 그래서 상점이 배틀 중에 의미를 갖는다 |

### 스태미나는 게임을 만들 때 쓰고, 3분에 한 점씩 저절로 찬다

스태미나가 나가는 자리는 **기획서 뽑기 · 개발 착수 · 디버그 · 교육 · 계약**
뿐이다. 보스를 잡는 데는 한 점도 들지 않는다 — 보스는 직원들이 **자기 체력**
으로 잡는다. 그래서 "이번 주에 뭘 할까" 와 "팀이 얼마나 버티나" 가 서로 다른
질문이 되고, 둘 다 답할 가치가 생긴다.

스태미나는 **실제 시간으로 3분에 한 점씩** 찬다. 게임을 꺼 둔 사이에도 차므로,
다시 켜면 그동안 지난 만큼 한 번에 들어와 있다. HUD 의 `STAM` 옆에 다음 한 점까지
남은 시간이 뜬다.

그래서 **다음 주로 넘기기에 값이 붙었다.** 한 번은 언제나 공짜지만, 아무것도
하지 않고 연달아 넘기면 코인이 1 → 2 → 3 으로 든다. 기획서를 쓰거나 개발에
들어가거나 계약을 받으면 — 돈이나 스태미나가 나가는 무엇이든 하면 — 다시
무료가 된다. 예전에는 이 버튼을 연타하는 것이 상도 계약도 판매도 가장 빨리
굴리는 방법이었다.

### 보스의 체력은 팀의 세기를 따라간다

예전에는 플랫폼과 장르만 보고 절대값을 뽑았다. 창업 직후 직원이 없는 시작으로
바꾸자 그 식이 무너졌다 — 레벨 1 세 명이 한 턴에 20씩 때리는데 데뷔작의 HP가
8,000이면 **296턴**이다. 실제로 그랬다.

그래서 기준을 바꿨다. HP는 **몇 번 때리면 끝나는가**로 정한다. 야심(플랫폼 ·
★등급 · 시리즈 · 장르)이 라운드 수를 정하고, 거기에 팀의 기대 데미지를 곱한
값이 세 마리의 총 체력이다. 강한 팀이 사는 것은 속도가 아니라 **품질**이다.

| | 라운드 | 실제 시간(1배속) | 주 넘김 |
|---|---|---|---|
| 데뷔작 (Lv1 · 3명 · 피처폰) | 26 | 약 60초 | 1~2회 |
| 중반 (Lv12 · 5명 · 스마트폰) | 44 | 약 85초 | 2회 |
| 후반 (Lv30 · 6명 · 콘솔) | 62 | 약 120초 | 3회 |

(12시드 평균, 밥을 한 번도 안 먹였을 때. 가방에 컵라면이 있으면 주 넘김은
그만큼 줄어든다.)

### 탈진 마감 — 쉬는 만큼 게임이 덜 만들어진다

예전에는 팀이 전원 쓰러지면 **다음 주로 넘기기**로 체력을 공짜로 채워 같은
보스를 계속 팰 수 있었다. 시간이 무한하면 상점의 음식은 아무도 사지 않는
물건이 된다 — 밥은 돈이 들고 기다림은 공짜니까.

이제 전원이 쓰러지면 그 단계는 **거기서 끝난다**. 자동 전투에서는 유예 8초가
지나면, 사무실에서는 주를 넘기는 순간에 마감이 걸린다. 남은 체력의 비율만큼
**못 만든 것**으로 기록되고, 그만큼 다섯 품질 축이 통째로 깎이고 버그가 붙는다.

| 남긴 체력 | 완성도 | 붙는 버그 |
|---|---|---|
| 한 단계를 20% 남기고 마감 | 약 96% | +2 |
| 한 단계를 80% 남기고 마감 | 약 88% | +6 |
| 세 단계를 모두 뻗은 채 마감 | 40% (하한 34%) | +27 |

품질은 '한 타격당 평균'이라서 일찍 끝낸다고 평균이 떨어지지 않는다. 즉
페널티가 없으면 탈진 마감이 **지름길**이 된다 — 그래서 완성도는 결과값에
곱한다. 결과창과 개발 중 진행 패널이 **같은 함수**를 보므로, 보고 있던 숫자와
완성 결과가 어긋나지 않는다.

### 직원 강화 💪 — 레벨이 크기라면 강화는 방향이다

레벨(아이템)과 경험치(출시)는 "이 사람이 전체적으로 얼마나 크는가"만 정한다.
**강화**는 그 위에 얹는 방향이다. 직원 탭에서 돈으로 산다 — 스태미나는 들지
않는다.

| 강화 | 효과 | 단계 |
|---|---|---|
| 💪 체력 단련 | 최대 체력 +10 | 12 |
| ⚔️ 공격력 훈련 | 데미지 +7% | 12 |
| ⚡ 속도 훈련 | 공격 속도 +5% | 8 |
| ✨ 번뜩임 훈련 | 번뜩임 확률 +2%p | 8 |
| 📐📟🎨🎧📡 강의 | 기획 · 개발 · 그래픽 · 사운드 · 소셜 +5 | 각 10 |

값은 단계마다 1.4~1.5배씩 오른다. 돈이 남아도는 후반에도 한 사람을 전부
채우는 것이 아니라 **누구를 어느 방향으로 키울지** 고르게 하려면, 이 지수가
계수보다 중요하다.

### 합성 — 고르면 바로 보여준다

게임 내용을 고르면 그 자리에서 **장르 ✚ 내용 ➜ 조합 보스** 팝업이 뜬다.
궁합 배율과 한 줄 평이 함께 나온다. 고르기 *전*에는 한 번도 만들어 본 적 없는
조합의 궁합을 감춘다 — 그게 발견의 재미다. 도감에 올라간 조합만 카드에
등급이 뜨고, 나머지는 `???` 다.

## 출시 → 실시간 판매 📈

보스 셋을 다 잡으면 **결과창 → 홍보 선택 → 출시 확인**이 그 자리에서 이어진다.
탭을 찾아 들어갈 필요가 없다.

출시하면 화면 **오른쪽 레일에 판매 카드**가 선다. 열두 주치가 1.5초에 한 주씩
흐르고, 막대가 하나씩 서고 꺾은선이 그 위를 잇고, **자금이 눈앞에서 오른다**.

**화면을 막지 않는다.** 예전에는 전체를 덮는 모달이라 그 15초가 곧 아무것도
못 하는 시간이었다 — 연출이 아니라 대기시간이었다. 이제 그동안에도 기획서를
뽑고, 직원을 키우고, 다음 게임에 착수할 수 있다.

### 곡선의 모양 — 오르고, 꺾이고, 식는다

예전에는 출시 주가 최고점이었고 그 뒤로는 내려가기만 했다. 실제로 팔리는
물건은 그렇게 움직이지 않는다: 처음에는 아는 사람만 사고, 입소문이 돌면서
몇 주에 걸쳐 올라가고, 정점을 찍은 다음에 식는다.

그래서 출시 유저는 **정점이 아니라 출발점**이다(약 42%). 정점은 보통 3주차에
서고 — 화제성이 높으면 빨리, 지속성이 높으면 천천히 — 그 뒤로는 잔존율에
따라 식는다. 식는 속도는 시간이 갈수록 조금씩 **빨라진다**. 안 그러면 지속성
높은 게임이 반년 뒤에도 같은 자리에 붙어 있어서 그래프에 끝이 없다.

### 수익 모델 — 크게 벌려면 크게 쓴다

부분유료는 상점 · 과금 서버 · 운영 도구를 같이 만들어야 하고, 장기운영은
거기에 몇 년치 콘텐츠 계획까지 얹힌다. 예전에는 셋이 같은 값이라 부분유료가
언제나 정답이었다.

| 모델 | 개발비 | 착수 스태미나 | 5년 평균 순이익 | 다 팔리는 데 |
|---|---|---|---|---|
| 유료 | ×1.00 | +0 | 약 55만 | 33주 |
| 부분유료 | ×1.70 | +2 | 약 78만 | 51주 |
| 부분유료 (장기운영) | ×2.60 | +4 | 약 91만 | 50주 |

(스마트폰 ★3 · 품질 중간대 25회 평균. 큰 모델은 더 벌지만, **먼저 내고 오래
기다린다** — 자금이 얇을 때는 유료가 옳은 답이다.)

### 판매 중 사건 📺

주마다 낮은 확률로 사건이 하나 붙는다. 그 주 매출이 그만큼 튀고, 유저 수에도
흔적이 남는다. 정점 전에는 좋은 쪽이, 지난 뒤에는 나쁜 쪽이 조금 더 잘 걸린다.

| 좋은 쪽 | 나쁜 쪽 |
|---|---|
| 📺 연예인 광고 +30~75% · 🎥 인기 스트리머 방송 · 💬 SNS 입소문 · 🏅 앱마켓 추천 · 🧩 대형 업데이트 | 🛠 서버 점검 · ⚔️ 경쟁작 출시 · 💢 악평 확산 (−10~38%) |

사건이 붙은 주는 막대의 **색이 다르다**(오르면 하늘색, 내리면 붉은색).
이유 없이 튀는 그래프는 그냥 잡음이다.

그 뒤의 꼬리는 같은 레일의 **판매 현황** 카드가 이어받는다: 이번 주 매출,
유저 수, 주차별 매출 막대, 지난주 대비 하락률, 마지막 사건, 그리고
**남은 수명**(정점 전이면 `📈 상승 중`).

## 직원 체력과 상점 🍜

직원에게 **체력**이 생겼다. 한 번 칠 때마다 줄고, 보스의 반격이 크게 깎는다.
**이것이 전투의 자원이다** — 스태미나가 아니라.
체력이 40% 아래로 떨어지면 '지침', 0이면 '탈진' — 데미지와 품질이 같이
떨어진다. 다만 **0이 되어도 힘이 0이 되지는 않는다.** 굶은 팀은 느려질
뿐 멈추지 않는다.

회복은 세 갈래다: **다음 주 휴식**, **상점의 음식**, 그리고 아레나 아래의
**도우미 트레이**(가방 속 음식을 그 자리에서 가장 지친 사람에게).

**스태미나도 마찬가지로 하루를 넘겨야만 차지 않는다.** 상점의 캔커피 ·
에너지 드링크 · 스페셜티 원두가 즉시 채워주고, **야근**(주 1회)은 돈과
직원의 체력·의욕을 스태미나로 바꾼다.

### 장비 — 직원마다 특색이 생기는 자리

상점의 **장비**는 가방을 거쳐 직원에게 장착된다 (한 사람당 3칸).
장비는 두 가지를 동시에 올린다.

- 그 사람의 **능력치** (→ 배틀 데미지가 오른다)
- 그 사람이 밀어 올리는 **품질 축의 상승폭**

즉 사운드 담당에게 **🎹 업라이트 피아노**를 사주면 사운드 수치만 오르는 게
아니라, 그 사람이 만드는 게임의 **화제성 +13% · 임팩트 +11%** 가 실제
완성 점수에 붙는다. 기획자에게는 아이디어 노트, 프로그래머에게는 기계식
키보드, 디자이너에게는 액정 타블렛, 네트워커에게는 서버 랙.

## 도감 📖

무엇을 모으는 게임인지 한 화면에서 보인다. **잡은 아이디어**(장르별 16종,
격파 횟수·최고 점수·최단 턴), **써본 소재**, **사본 아이템**, **거쳐간

소재 칸은 세 가지 상태를 갖는다: 아직 못 뽑은 것은 `???`, 뽑았지만 아직
게임에 안 써 본 것은 이름만 흐리게, 실제로 만들어 본 것은 금색이다.

## 경쟁사와 주간 판매 차트 👑

출시하고 나면 볼 것이 자금밖에 없었다. 20만 명이 많은 것인지 적은 것인지는
옆에 다른 회사의 숫자가 있어야 알 수 있다.

라이벌 스튜디오 셋이 각자의 속도로 게임을 낸다 — **빅픽처 게임즈**(느리지만
낼 때마다 크다), **톡톡 스튜디오**(자주 내고 작다), **미드나잇 랩**(중간,
편차가 크다). 우리 운영작과 라이벌 게임이 **같은 표에서 유저 수로 줄을 서고**,
📈 운영 탭 맨 위에서 그 표를 본다.

라이벌의 규모는 **우리 최고작을 따라간다.** 고정 숫자로 두면 1년차에는 넘볼 수
없는 벽이고 5년차에는 아무도 아니게 되기 때문이다. 1위를 지킨 주에는 팬이
늘고, 1위를 뺏기면 누구에게 뺏겼는지 알려준다.

## 도우미 🐈

코인 5로 뽑는 마스코트 12종. ★1 사무실 고양이부터 ★5 전설의 프로듀서까지.

- **낀 도우미가 개발 배틀의 숫자를 민다** — 한 방, 번뜩임 확률, 보물상자 확률,
  재촉 쿨다운, 개발 중 체력 회복, 기획서 등급.
- **자리는 랭크가 연다.** 처음에는 하나, 랭크 5에 둘, 랭크 12에 셋.
- **겹쳐 뽑으면 레벨이 오른다.** 뽑기가 "이미 있는 것" 을 뱉는 순간 손해로
  느껴지면 두 번 돌리지 않게 된다.

효과는 일부러 작다. 도우미가 팀보다 세지면 게임은 직원을 키우는 것이 아니라
뽑기를 돌리는 것이 된다. 🛒 상점 탭에서 뽑고 장착한다.

## 소리 🔊

효과음이 붙었다. **에셋 파일은 한 장도 없다** — WebAudio 의 오실레이터와
노이즈만으로 그 자리에서 만든다 (`src/ui/sound.js`). 파일 0바이트, 첫 로딩
0초, 오프라인에서도 그대로 난다.

타격·번뜩임·격파·보물상자·콤보(누를수록 음이 올라간다)·출시 팡파르·수상·
주간 정산까지. 회사 탭 → 설정에서 끌 수 있고, 그 선택은 기기에 남는다.

브라우저는 오디오를 **사용자 제스처 안에서만** 열어 주므로, 첫 터치 전까지는
아무 소리도 나지 않는다. 그건 버그가 아니라 아직 화면을 안 만진 것이다.

## 모바일

세로 390px 안에 사무실과 패널이 함께 들어가야 하므로 레이아웃 전체가
가로 기준으로 짜여 있다.

- **패널은 접힌 채로 시작한다.** ☰ 로 슬라이드해 열고, 열면 배틀 바가
  옆으로 비켜난다. 폭이 900px 이상이면 접는 버튼 자체가 사라진다.
- **안전 영역**(`env(safe-area-inset-*)`)을 모든 고정 요소에 적용한다.
  가로에서는 노치가 화면의 한쪽 변을 통째로 먹는다.
- **`100vh` 를 쓰지 않는다.** 모바일에서 `100vh` 는 "주소창이 숨겨졌을 때의
  높이"라 대부분의 시간 동안 틀리다. `visualViewport` 를 추적해 `--vh` 로
  넣는다.
- **품질 티어**를 GPU 문자열·코어 수·메모리로 판정해 그림자 해상도(1024–2048),
  DPR 상한(1.0–2.0), 블룸 단계(3–5)를 조절한다. `?q=low|mid|high` 로 강제 가능.
  DPR 상한이 가장 큰 레버다 — 3배 화면은 1배의 9배 픽셀이고, 팔 길이에서는
  대부분 구분하지 못한다.
- 풀 투 리프레시, 더블탭 줌, 롱프레스 선택, iOS 고무줄 스크롤을 모두 막는다.
- 첫 터치에서 전체화면과 가로 잠금을 시도한다 (거부돼도 게임은 그대로 돈다).

### 주소가 매번 바뀌는 이유와 고정 주소

Vercel 은 배포마다 **고유한 프리뷰 주소**를 새로 만든다
(`game22-<해시>-....vercel.app`). 그래서 `npx vercel` 만 치면 매번 다른
링크가 나온다. 프로젝트에는 그와 별개로 **프로덕션 별칭**이 하나 있고,
이 주소는 절대 바뀌지 않는다:

> ## <https://game22-indol.vercel.app>

이 별칭을 최신 배포로 옮기는 방법은 둘 중 하나다.

```bash
npx vercel --prod        # 지금 있는 코드를 바로 프로덕션으로
```

또는 GitHub 저장소가 연결되어 있으므로 **기본 브랜치에 머지**하면
자동으로 프로덕션 배포가 돌고 별칭이 따라온다. 다른 브랜치에 푸시하면
프리뷰 주소만 생기고 고정 주소는 그대로다.

같은 저장소를 보는 프로젝트가 하나 더 있어서 이 주소도 함께 산다:
<https://social-dev-story-3d.vercel.app>

### 캐시

`vercel.json` 은 캐시 헤더만 정한다 — `sw.js` 와 `src/` 는 매번 재검증,
아이콘과 `assets/` 는 1년 불변. 서비스 워커가 실제 캐싱을 담당하므로
HTTP 캐시를 길게 잡으면 업데이트가 전파되지 않는다.

`sw.js` 의 `ASSETS` 목록은 `src/` 와 `icons/` 를 훑어 생성한 것이다.
파일을 추가하면 목록과 `CACHE` 버전을 함께 갱신해야 한다.
`assets/monsters/*.glb` 는 일부러 프리캐시하지 않는다 — 셋이 합쳐 1MB에
가깝고 프로젝트당 한 종만 쓰므로, 런타임 핸들러가 처음 쓸 때 캐시한다.

## 구조

```
src/
  core/     math · gl · color · meshbuilder · bake      순수 렌더 유틸
            gltf                                       GLB 리더 + 스켈레톤 솔버
  render/   shaders · renderer · camera                 PBR 파이프라인
            skinned                                    스킨드 glTF (보스 몬스터)
  char/     rig · poses                                 16본 스켈레톤 (직원)
  world/    palette · props · office                    지오메트리만
            placed                                     놓인 가구 → 메시 + 책상
            agents · boss                              직원 상태 기계 · 몬스터
            arena                                      보스 세트장 3종
  game/     data · state · staff · project · economy    순수 시뮬레이션
            furniture · monsters · tutorial            가구 · 몬스터 · 튜토리얼
            dialogue                                    회의 대사 (한국어)
            events                                      주간 이벤트 · 세일즈 태스크
  ui/       hud · device · style.css                    DOM 오버레이
            firstperson                                 1인칭 이동 · 상호작용
  main.js                                               셋을 묶는다
assets/monsters/  cat.glb · orc.glb · demon.glb         유일한 외부 에셋
tools/    balance · flow · features · meeting · probe   테스트 하네스
```

경계가 분명하다. `game/` 은 WebGL을 모르고 (그래서 브라우저 없이 밸런스를
돌려볼 수 있다), `world/` 는 게임 규칙을 모르고, `core/` 는 둘 다 모른다.

## 그래픽

**사무실에는 텍스처 파일이 하나도 없다.** 모든 표면은 프래그먼트 셰이더
안의 **프로시저럴 머티리얼** 16종이다 — 카펫 섬유, 나뭇결, 브러시드 메탈,
직물 조직, 아크릴 천장타일, 피부, 머리카락, 그리고 모니터마다 다른
살아있는 화면.

보스 몬스터만 예외다. 외부 캐릭터 팩(Quaternius, CC0)이라 자기 아틀라스를
가지고 오고, 전용 셰이더(`FS_SKIN`)로 그린다 — 4-weight 스키닝, 조인트
행렬은 RGBA32F 텍스처에 넣고 `texelFetch` 로 읽는다. 오크의 본 43개는
mat4 유니폼 배열의 WebGL2 최소 보장치를 통째로 먹어버리고, 그 최소치를
그대로 보고하는 폰 드라이버가 실제로 있다.

파이프라인:

```
그림자 뎁스 (2048, 12탭 포아송 PCF, 슬로프 바이어스)
   ↓
HDR 씬 (RGBA16F, Cook-Torrance GGX, 표면 그래디언트 범프, 해석적 하늘 IBL)
   ↓
브라이트 패스 (Karis 평균) → 5단 블룸 다운/업샘플
   ↓
컴포짓 (노출 · ACES · 비네트 · 그레인 · 색수차) → FXAA → 캔버스
```

돌하우스 뷰는 두 가지 컷을 쓴다. 카메라와 시점 사이에 선 벽은 4×4 오더드
디더로 녹아 사라지고, 보고 있는 층 위쪽은 통째로 잘려나간다.

## 테스트

```bash
node tools/balance.mjs 12345 10   # 밸런스 시뮬레이션 (브라우저 불필요)
node tools/sloppy.mjs             # 최악의 플레이로 파산 방지선 확인
node tools/monster.mjs            # 보스 에셋 검증 (브라우저 불필요)
(setsid python3 -m http.server 8123 &)
node tools/probe.mjs              # 부팅 확인
node tools/meeting.mjs            # 회의 연출
node tools/flow.mjs               # 전체 플로우 · 배치 조작 · 세이브 이관 42개 검사
node tools/battle.mjs             # 상점·소재 뽑기·장비·체력·도감·1인칭 26개 검사
node tools/raid.mjs               # 보스 아레나 3연전 · 세트장 · 판매 패널 11개 검사
node tools/shots.mjs              # 눈으로 볼 것들의 스크린샷
```

`flow.mjs` 의 배치 조작 검사는 CDP 로 **진짜 멀티터치**를 쏜다. 손가락 두 개로
끌었을 때 카메라가 한 톨도 안 움직이는지가 그 검사의 전부다 — 그 계약이
깨졌던 것이 "책상을 옮기려는데 화면이 움직인다" 의 정체였다.

에셋을 다시 만들 때:

```bash
node tools/gltf2glb.mjs in.gltf out.glb Idle,Walk,Punch,HitReact,Death
node tools/monster.mjs
```

## 현재 상태

M1 (뼈대) 완료. 렌더러, 3D 오피스, 캐릭터, 개발 배틀, 회의실 연출,
출시·운영, 랭크, 직원 육성·전직·환생·특성, 연구·홍보·계약·유행,
사무실 층 구매, 세이브까지 한 바퀴가 돈다.

여기에 **창업(회사명 + 지원금) → 가구 구입 → 배치 → 채용**으로 시작하는
도입부, **보스 몬스터**, **긴급 지원금**, 튜토리얼이 붙었다.
여기에 **3D 보스전**(페이즈·반격·약점·집중 개발), **실시간 진행 패널**,
**직원 체력**, **상점과 가방**(음식·음료·장난감·도구·장비), **야근**,
**도감**, **1인칭 걷기 모드**, **화면 밝기 설정**이 올라가 있다.

그 다음으로 **보스별 전용 세트장**, **카메라 조이스틱**, **소재 뽑기**,
그리고 회사 탭의 **테스트 도구**가 붙었다. 같이 고친 것:

- 배치 모드에서 손가락이 둘 이상 닿으면 가구 드래그가 카메라 팬으로
  바뀌던 문제 — 이제 배치 중 캔버스는 카메라를 건드리지 않는다
- `hud.js` 안에 `panelShop` 이 두 번 선언돼 **상점 탭이 가구점을 열던** 문제
  (나중 선언이 조용히 이겼다. 음식·장비·도감이 통째로 화면에서 사라져 있었다)
- 소재 '스포츠' 와 장르 '스포츠' 의 이름 충돌 → 소재를 '축구' 로
- `focusBoss()` 가 아무것도 돌려주지 않아 **👾 보스** 버튼이 성공해도
  "아직 나타나지 않았습니다" 를 띄우던 문제

그 다음으로 **탈진 마감**, **직원 강화**, **봉우리 판매 곡선과 판매 중 사건**,
**수익 모델별 개발비**가 붙었다. 같이 고친 것:

- 팀 전원 탈진 화면이 파티 카드 **뒤에** 깔려 있어서, 반투명하게 보이는데
  버튼은 눌리지 않던 문제 — 형제 순서상 `.afoot` 이 나중에 그려졌다.
  쌓임 순서를 명시하고 배경을 진하게 깔았다
- 직원이 많으면 파티 카드 두 줄이 화면 아래 절반을 먹어 **보스가 안 보이던**
  문제 — 인원수에 따라 카드가 줄고, **👥 팀 접기**로 통째로 접힌다
- 디버그가 `finished` 를 다시 쏘는 바람에 버그를 잡을 때마다 완성 팝업이
  다시 뜨고 그 확인이 다시 홍보 선택으로 이어지던 **무한 반복** — 결과 →
  홍보 → 출시는 이제 게임 하나에 한 번만 흐른다
- 프레임 루프의 예외 하나, 또는 WebGL 컨텍스트 회수로 rAF 가 끊기면 3D가
  **영구히 흰 화면**(body 배경 `#c8cbcf`)으로 남던 문제 — 루프는 무슨 일이
  있어도 다음 프레임을 예약하고, 컨텍스트가 날아가면 저장하고 다시 불러온다
- `nextWeek()` 이 판매 중이라고 달력을 막아, 첫 출시 뒤 헤드리스
  시뮬레이션이 통째로 얼어붙던 문제 (5년에 1작품이 찍혔다)

밸런스는 `game/` 을 Node에서 그대로 돌리는 헤드리스 시뮬레이션으로 잡았다
(10년치 × 5시드, 그리고 아무것도 안 하는 최악의 플레이로 파산 여부 확인).
결과 표는 [계획서의 밸런스 절](docs/GAME_DESIGN.md#밸런스-헤드리스-시뮬레이션으로-검증)에 있다.

M2 이후 항목은 [계획서](docs/GAME_DESIGN.md#4-마일스톤) 참고.
